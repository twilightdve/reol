# site-check

サイトの今の状態を 4 つの領域で測り、前回の記録と比べて報告する。

| 引数 | 領域 | 測る先 | 目安の時間 |
|---|---|---|---|
| `content` | 内容と、検索に見つけてもらうための付け方 | `public/` の HTML 全部(ブラウザは使わない) | 1 分 |
| `a11y` | アクセシビリティ(axe-core、独自チェック、キーボード操作) | ローカルで配った `public/` | 10 分 |
| `design` | 見た目(デザインの決まりに関わる数、画面写真) | ローカルで配った `public/` | 5 分 |
| `perf` | 速さ(Lighthouse) | 本番 | 10 分 |
| `all` | 上の全部 | | 30 分 |

時間は 2026-11-17 に測った時のもの(測定だけ。見て判断する分と報告を書く分は別)。

引数: `$ARGUMENTS`(空なら `all`。複数を空白で並べてもよい)

調べ方の根拠と、このサイトで試して分かったことは `plan/76-site-evaluation-methods.md`。最初の評価は `plan/77-site-evaluation-2026-11.md`。

## しないこと

- 見つけた問題をその場で直さない。直すのは、報告を読んだユーザーに頼まれてから。
- デプロイしない。ビルドも、頼まれるか確かめてからにする(下の「測る前に」)。
- 記事の原稿を書き換えない。
- GA・Search Console・スプレッドシート・Supabase に書き込まない。設定も変えない。
- 重い処理を重ねない。スクリプトは 1 本ずつ順に動かす(メモリ不足で PC が落ちたことがある)。
- サブエージェントに分けて同時に走らせない(同じ理由)。

## 置き場所

- `scripts/` 測定の道具。全部 `node .claude/skills/site-check/scripts/<名前>.js` で動かす。
- `config.json` 測るページ、幅、本番の URL、独自デザインのページなど。ページを足す・外す時はここ。
- `package.json` 測定に使う外の道具(lighthouse・axe-core)の版。サイト本体の `package.json` とは分けてある。
- `history/<日付>.json` 回ごとのまとめ。**コミットする**(次の回が比べる相手)。
- `.site-check/<日付>/`(リポジトリの直下。gitignore 済み) 生の出力と画面写真。コミットしない。

## 手順

### 1. 測る前に

```
node .claude/skills/site-check/scripts/status.js
```

出てきたものを読んで決める。

- **重い処理が動いている**(gatsby、Lighthouse など)→ 終わるまで待つ。止めるのはユーザーに聞いてから。
- **道具が入っていない** → `npm install --prefix .claude/skills/site-check`。
- **ローカルのビルドが無い・古い** → `content` `a11y` `design` は古い版を測ることになる。ユーザーに伝えて、ビルドするか、今ある版で測るかを聞く(ビルドは重く、シートのデータも取り直す)。聞けない時は今ある版で測り、報告の頭に版を書く。
- **本番の版と HEAD が違う** → `perf` は本番の版、ほかは HEAD の版を測ることになる。報告に両方の版を書く。直しの効果を速さで確かめたいのに、まだデプロイしていない時は、そのことを伝える(ローカルで測った点は本番より低く出るので、代わりにはならない)。

### 2. 内容 (`content`)

```
node .claude/skills/site-check/scripts/content.js
node .claude/skills/site-check/scripts/extlinks.js   # 外へのリンク。読みものから張っている分だけ
```

`content.js` はサイトマップ、canonical、noindex、hreflang、title と description、OGP、JSON-LD、見出し、本文の短いページ、訳されていないページ、切れた内部リンク、追跡パラメータ、画像の alt と寸法を全ページで数える。

`extlinks.js` は外のサイトへ 1 つの URL につき 1 回ずつ読みに行く。401・403・429 は「機械を断っている」だけなので、切れたとは書かない(未確認)。

### 3. ローカルで配る (`a11y` `design` の前に)

```
node .claude/skills/site-check/scripts/serve.js      # バックグラウンドで動かす。ポートは config.json の localPort
```

`gatsby serve` は使わない(重い)。測り終わったら必ず止める(手順 6)。

### 4. アクセシビリティ (`a11y`)

```
node .claude/skills/site-check/scripts/a11y.js       # 38 ページ × 2 幅 × 2 テーマ
node .claude/skills/site-check/scripts/keyboard.js   # Tab で進んだ時の見え方
```

### 5. 見た目 (`design`)

```
node .claude/skills/site-check/scripts/design.js     # 数と画面写真
node .claude/skills/site-check/scripts/sheet.js      # 写真を並べた 1 枚(.site-check/<日付>/sheets/)
```

並べた写真は Read で開いて、自分の目で見る(手順 9)。

### 6. 配信を止める

```
pkill -f "site-check/scripts/serve.js"
```

### 7. 速さ (`perf`)

ローカルの測定が全部終わり、配信も止めてから動かす。

```
node .claude/skills/site-check/scripts/perf.js       # 本番の 12 ページ。スマホの条件で 3 回、PC で 1 回
```

途中で止まっても、同じ日ならもう一度動かせば続きから回る。CLS が 0.1 を超えたページの原因を探す時は、配信を動かして `cls.js --pages <ページ>`(`--strip "content-visibility:auto"` のように、疑った書き方を抜いて比べられる)。

### 8. 前回と比べる

```
node .claude/skills/site-check/scripts/report.js
```

今回のまとめを `history/<日付>.json` に書き、領域ごとに「その領域を測った一番新しい回」との差を表で出す。測っていない領域は書かれない。

### 9. 見て判断する

機械の数だけでは分からないものを、自分で見る。全部は見られないので、何を見たかを報告に書く。

- **見た目**: 並べた写真を見て、決まり(下)に合わない画面、ほかと揃っていない画面、前回から変わった画面を挙げる。
- **アクセシビリティ**: axe の incomplete(機械では決められないもの)、自前の背景を持つページのコントラスト、キーボードで止まる順番。
- **内容**: 記事を数本読む(新しく出た記事を優先)。誰が・どうやって・なぜ書いたかが伝わるか、出典があるか、題と中身が合っているか。機械の数(本文が短い、など)を、そのまま「薄い」と言い換えない。

ユーザーに見た目の判断をあおぐ時は、文字で聞かずに写真を見せる(`sheet.js --pages … --out <名前>.png` で選んだページだけの 1 枚を作り、SendUserFile で送る)。

### 10. 報告を書く

`plan/<次の番号>-site-check-<年>-<月>.md` に書き、`plan/README.md` の表に 1 行足す。日本語で書く。順番は次のとおり。

1. **結論**: 前回から良くなったもの・悪くなったもの・変わらないもの。3〜5 行。
2. **測った版と範囲**: HEAD、本番の版、ビルドの日時、道具の版、測った領域、測っていない領域。
3. **先に直す価値が高い順の一覧**: 1 件ごとに、何が・どこで(ページとファイル)・確かさ・前回からあったか。
4. **領域ごとの結果**: 数の表と、前回との差。
5. **見て判断したこと**: 見たページと、気づいたこと。
6. **測れていないもの**: 下の「毎回書くこと」。
7. **次にやること**

確かさは 4 つに分けて書く。

- **確認**: 機械の測定で出て、自分でも中身を見て確かめた。
- **要確認**: 機械は挙げたが、問題かどうかは人の判断が要る(意図した表現かもしれない、など)。
- **未確認**: 測れていない、確かめられなかった。
- **評価者の判断**: 数ではなく、見て・読んでそう思った。

書き終えたら、作業用のブランチで `history/<日付>.json` と報告をコミットする。`.site-check/` はコミットしない。

## 結果の読み方(このサイトで分かっている落とし穴)

1. **コントラスト**: `html` と `body` は透明で、色は奥の固定レイヤーが出している。axe はそのままだと白地と読み、暗いテーマで大量の誤検出を出す。`a11y.js` は測る間だけ `html` に本当の地色を入れている。自前の背景を持つページ(`config.json` の `ownBackgroundPages`)には入れないので、そこのコントラストの値は当てにせず、人が見る。
2. **速さは本番で、3 回の中央値**: ローカルで配ったものは本番より点が低く出る(HOME で 63 と 81)。1 回の点は数点ぶれるので、前回の幅の中の変化は「変わった」と書かない。
3. **CLS**: Lighthouse は読み込み直後のずれ(`hadRecentInput` が付くもの)も数える。`cls.js` も捨てずに出す。実際の利用者の CLS がどうかは、この測定では分からない。
4. **独自デザイン**: 楽曲記事は記事ごとに独自のデザインを持つのが決まり。グラデーションや光、トークンに無い色は意図した表現で、違反ではない。`design.js` は独自デザインのページを合計から外し、数だけ別に出す(一覧は `src/components/songArticles/designs/` と `config.json` の `ownDesignPages` から決まる)。
5. **見た目の決まり**(plan/71、unslop): カードを並べない(枠は動画・地図・画像と押すものだけ。行と罫線で組む)。文字は 11px 以上。余白は 4px 刻み。グラデーション・ぼかし・光・絵文字アイコンを使わない。動かすのは色・背景・枠・透明度・transform だけ。黄は選択と主な操作、青は決まった意味だけ、ほかは無彩色。`design.js` の「黄: 押すものでない」は、選択中の印や見出しの飾りも拾うので、数のまま違反とは書かない。「絵文字」は色つきの絵で出る字だけ。✓ や → のような字の形の印は「記号」に分けてあり、アイコン代わりかどうかは見て決める。
6. **外へのリンクの 403**: 判定できない。切れたと書かない。
7. **キーボードの「隠れる」**: 固定の部品(下部タブ、「上へ戻る」)の下か画面の外に、フォーカスした物がある時だけ数える。地図のピン同士のような重なりは「ほかの重なり」に分けてある。Tab は 1 ページ 60 回までなので、長いページの後ろは歩いていない。
8. **ほかの人の名前**: 診断のタイプ詳細とツアーナビには、利用者のアカウント名が出る。`config.json` の `privatePages` では、その読み込みを止めて測っている(だからその部分は測れていない)。axe の例に残すセレクタも、長い数字(投稿の番号)は伏せてある。手紙の本文も含め、ほかの人の名前や書いたものを、報告・コミット・ユーザーへ送る画像に写さない。
9. **機械で 0 件でも「適合」「問題なし」とは書かない**: axe が見つけられるのは問題の一部。
10. **数が大きく動いた時は、まず測り方を疑う**: 道具の版(`report.js` が違いを出す)、測ったページ(`config.json`)、ビルドの版、404 になったページ(まとめの `notOk`)。

## 毎回書くこと(測れていないもの)

- 実際の利用者の数字(CrUX、GA4 の Web Vitals)。取れた時だけ書き、取れない時は「取っていない」と書く。
- iPhone の実機、Safari、読み上げ(VoiceOver)での確かめ。Playwright の WebKit で見たものを実機で見たとは書かない。
- 抜き取りで見ていること(a11y と見た目は `config.json` の `samplePages`、速さは `perfPages`)。
- 開いた後に読み込む内容(手紙、診断の仲間 など)は、`content.js` の数に入らないこと。

## ページを足す・外す

`config.json` を直す。ページを入れ替えると、合計は前回と比べられなくなる(ページごとの数は比べられる)。入れ替えた時は、報告にそう書く。404 になったページは `a11y` と `design` のまとめの `notOk` に出るので、外すか、新しい URL に替える。
