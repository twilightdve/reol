## きっかけ

ユーザーから(2026-11-13)。「↓これ次の作業」として、PHOTO を読みものへ統合する移行計画(計画書・棚卸しの一覧・棚卸しの JSON)を受け取った。

この資料は、その範囲でやったこと・決めたこと・確かめたこと・残っている確認をまとめたもの。**公開・デプロイ・main への取り込み・ナビの切り替えはしていない。** 旧 PHOTO(`/photo/`)は何も変えていない。

## 結論

- 読みものに、楽曲記事と並ぶ2つ目の種類「記録」(`kind: "record"`)を足した。写真と動画を本文の好きな位置に置ける、共通のテンプレート1つで描く(記録ごとの React・CSS は持たない)。
- 旧 PHOTO の 89 件を 48 のまとまりに割り当てた台帳を作り、「どの写真・動画・リンクがどの記録に入ったか」を機械で検査できるようにした。
- 先行2本(福岡の聖地の3件をまとめた1本、ラッキーフェス 2023)を下書きにし、プレビュー用のビルドで表示を確かめた。
- 既存の楽曲記事・ガイド・HOME の「読みもの」は、公開中のサイトとページ情報が同じ(差はシリーズの定義が2つ増えた点だけ)。

## 作ったもの

### 記録という種類

| 項目 | 内容 |
|------|------|
| 置き場 | 公開したものは `content/articles/<記事ID>/`(楽曲記事と同じ)。下書きは `.articles-local/`(git に入らない) |
| 記事ID | `record-…`(例 `record-luckyfes-20230716`)。いいねの記事IDの決まり(英小文字・数字・ハイフン)に収まる |
| 本文 | Markdown。先頭の H1 が題名。写真と動画は ```` ```media ```` ブロックで置く(`photo`・`youtube`・`gallery`)。生の HTML は通さない |
| 写真と動画の定義 | `media.json`。ID・画像のパス(`src/images/` の下だけ)か YouTube の動画ID・代替テキスト・表紙にする写真 |
| 改ざん・取り違えの検知 | 本文+`media.json`+画像の中身から作るハッシュ(`contentSha256`)を取込の時に控える。取込の後でどれかが変わると、取込し直すまでビルドも公開も止まる |
| 画像 | ビルドの時に幅 800・1600 の WebP と、表紙(800×420)・OGP(1200×630)を作って `public/articles-media/<slug>/` に置く。ファイル名は写真のIDと中身のハッシュから作り、元のファイル名やリポジトリの中のパスは出さない |
| 表示 | 共通テンプレート `src/templates/record-article.tsx` と `RecordBody`。写真は切り抜かない(縦の写真も元の比率)。複数の時は2枚ずつ、奇数なら最初の1枚を大きく。狭い画面では本文の順のまま縦に。写真を押すと拡大表示(前後へ送れる・Esc で閉じる)。動画は既存の `PlayerSlot`(縦の動画は縦のまま) |
| 一覧・シリーズ | 読みものの一覧とシリーズのページに、表紙カードで出る。カードの上の小さい行は出来事の日付 |
| 並び順 | 記録は出来事の日付の新しい順(過去の記録をまとめて公開しても、出来事の順に並ぶ)。楽曲記事の並びは変わらない |
| HOME の新着・RSS | `announce: false` の記録は、一覧・シリーズ・サイトマップには出るが、HOME の新着と RSS には出ない(過去の記録をまとめて出しても新着を埋めないため)。先行2本は `false` にしてある |
| 公開の種類 | 楽曲記事と同じ(下書き・限定公開・予約公開・公開)。公開済みの記録の slug と `announce` は後から変えられない |
| 記事別デザイン | 記録には要らない(共通テンプレートのため)。楽曲記事の「記事ごとの独自デザインが要件」はそのまま |

`npm run articles:photo`(`scripts/articles/photo-migration.ts`)。台帳は `.articles-local/photo-migration/ledger.json`(git に入らない)。

## 手順

### 楽曲記事(変更なし)

`npm run articles:import` → 記事別デザイン → `npm run articles:preview` → `npm run articles:publish -- --id … --revision N` → `npm run articles:og` → コミット → デプロイ。

### 記録

1. 雛形を作る: `npm run articles:photo -- generate --group <まとまりのID> --write`(`.articles-local/records/<記事ID>/` に `body.md`・`media.json`・`meta.json`)
2. 写真を見て代替テキストを書く。関連リンクの見出しを直す。表紙にする写真を選ぶ
3. 取込: `npm run articles:record -- --id <記事ID>`(検査だけなら `--check`)
4. 台帳の検査: `npm run articles:photo -- check`
5. プレビュー: `npm run articles:preview`
6. `.articles-local/staging/<記事ID>/editorial.json` で slug を決め、`slugProposed` を `false` に
7. 公開: `npm run articles:publish -- --id <記事ID> --revision N`(`--unlisted`・`--at` も楽曲記事と同じ)
8. コミット → 頼まれた時にデプロイ

## 決めたこと(聞かずに決めたもの)

| 決めたこと | 理由 |
|-----------|------|
| X の関連投稿は埋め込まず、リンクだけ | 埋め込みは読み込みが重く、記事の主役が写真であるため。変えたければ言ってください |

| リンクに utm は付けない | 計画書には付ける案があったが、「リンクに utm を付けない」という前の指定を優先した |
