## 1. 最優先と、その理由

**最優先: 公演ページを「公演の前と後に開く理由のあるページ」に変える。新しい島は増やさず、すでにあるセトリ・読みもの・公式リンクを、公演という時機に束ねる。**

理由は三つ。

1. **人が来たのは、X で URL を渡した時だけ。その山は、公演や記念日の時機と重なりやすい。** 人数の山は、どれも X で渡した URL が起こしている(参考: 3/5〜7 診断、5/13〜16 と 7/11〜13 は HOME、確認: 11/9 手紙企画)。うち二つは日付のある出来事と重なる(7/10 のツアーファイナルの直後、11/9 の誕生日)。美辞学ナビは山ではなく、ツアーの間じゅう繰り返し開かれた(参考: 直接の訪問が89人で471セッション)。それ以外の日は1日4〜20人(確認: 10/30〜11/11)。次の7週間に公演が6日ある(11/20、11/29、12/6・7、12/15、12/26)。
2. **いちばん押されている入口の先が、いちばん弱い。** HOME の入口カードのクリック43回のうち20回が「公演情報・セトリ」(確認)。その先の公演ページは、見出しとタイトルが「東京」「大阪」だけで、これからの公演にも「LIVE ARCHIVE」と出て、地図の下に「セットリスト情報は現在登録されていません」があるだけ(確認: `/live/ousaka-12/`、`/live/toukyou-10/`、`src/templates/live-item.tsx`)。
3. **いちばん手間をかけた資産(読みもの21本)が、公演ページからだけ繋がっていない。** 曲ページ⇄記事は繋がり、記事→公演も一部の記事にあるが、公演→記事が無い。2024年の「極秘LEGIT」東の宴は、16曲のうち11曲に読みものがある(確認: データ突き合わせ)。その続編「極秘LEGIT #2」が 11/29 と 12/15 にある。

いちばん強い反論も先に書く。**公演ページはツアー中でもほとんど見られていなかった**(参考: 3/1〜8/5 でファイナル `/live/toukyou-9/` は3PV・1人。同じ期間に美辞学ナビのトップは430人)。効いたのは「テンプレートの出来」ではなく「名前のある企画を X で渡したこと」だった可能性が高い。だから、テンプレート全体を磨くところから始めず、**極秘LEGIT #2 の2ページを「X で渡せる1枚」に仕立てて試す**ところから始める(4章 A)。

### 各案

**A. 公演ページを、公演の前と後に開くページにする**
- 誰が・いつ: これから行く人(公演の数日前)、行った人と行けなかった人(公演の翌日)。HOME から「公演情報・セトリ」を押した人。
- 増えるもの: 行く前に「前回は何をやったか」と、その曲の読みものに着く。行った後に「今夜のあの曲は何年ぶりだったか」が分かる。年単位の「久しぶり」を出せるのは、全公演のセトリを曲の UUID で持っているこのサイトだけ。
- 現状と根拠: 2-3、2-4 のとおり。
- 既存との差: 新しいページは作らない。名前の直し、これからの公演の表示、セトリの行の注記(読みもの・初披露・◯年ぶり)、公式ページへのリンクを、今のテンプレートに足す。美辞学ナビ(会場調査・参加者マッチング)の復活ではない。「ツアーナビの常設化は検討対象外」という以前の決定はそのまま。
- 使えるもの: `live.json`(`siteUrl`、セトリの UUID)、記事の `songRefs`、`/live/guide/`、OGP 画像。追加で要るもの: 「極秘LEGIT #2 の前回は極秘LEGIT(2024)」のような、続きものの対応(1行の手書きで足りる)。
- 工数: 最小(名前＋これからの公演＋読みものの印)1〜2日。注記(初披露・◯年ぶり)を足して＋1〜2日。継続の手間は、今もしているセトリの入力だけ。外部依存なし。
- 期待と実証: 実証済みは「公演前の企画は人を集めた」「入口カードは公演がいちばん押される」まで。「公演ページから読みものへ進む」は期待で、まだ誰も試せていない(リンクが無いので)。

**B. 読みものの新シリーズ「ツアーを読む」**
- 誰が・いつ: ツアーに行った人、行けなかった人、曲の記事を読み終えて次を探す人。
- 増えるもの: 1曲ずつの読みでは出てこない「今のReolが過去の曲をどこに置いているか」。セトリの表ではなく、筋のある文章として。
- 現状と根拠: 2-4 の美辞学ツアーの発見。`/live/setlist-grammar/` は同じ種類の材料を表で出して、読まれていない。
- 既存との差: 既存21本は1曲が単位(006 は「1公演から1曲」)。これは「1ツアーから多くの曲」。既存の記事5〜7本への自然な入口になる。改善計画の案H(セトリの文法)を、道具から読みものへ作り替える位置づけ。
- 使えるもの: 24公演のセトリ、ツアーファイナルの音楽ナタリーの記事(データにリンクあり。本文は今回読んでいない)、公式のツアーページ。追加で要るもの: 本人の発言(セトリやツアーの意図に触れたもの。未確認)、セトリの記録の出典の確かめ、書き手自身が見た公演の記憶。
- 工数: 事実の表と、公演×曲の図の部品 1〜2日。取り込みの `kind` を公演・ツアーに広げる 0.5〜1日。記事別デザインは今までと同じ(1〜2日)。継続は、書くと決めたツアーの分だけ。
- 期待と実証: 実証はまだ無い。短い版で試せる(4章 B)。

**C. 「2026年のReol」— 年の記録ページ**
- 誰が・いつ: 年末年始に一年を振り返るファン。手紙企画で来た人の、次の行き先。
- 増えるもの: その年のリリース、公演、よく演奏された曲、初披露、久しぶりの曲、その年に出た読みものを、上から読める1枚に。参戦記録がある人には「自分が行った公演・生で聴いた曲」を重ねる(任意)。
- 現状と根拠: `/letters/` に「今年の音楽も、今年のライヴも」の年表がすでにある(誕生日の年。公演29件と X の投稿)。締切(12/20)の後、この年表の行き先が決まっていない。年の単位で読めるページは他に無い(タイムマシンは月のスライダーで、13日で1人)。
- 既存との差: タイムマシン・On This Day・ヒートマップは「道具」。これは年に一度の「読むページ」。
- 工数: 個人の重ね合わせなしで 1.5〜3日。重ね合わせとカードで＋1〜2日。翌年からは手作業なし(年を引数にした生成にすれば)。
- 期待と実証: 「年末は振り返る」は一般的な期待。**共有カードは、このサイトではまだ使われた実績が見えない**(`heard_share_card` は確認した二つの期間でゼロ)。個人の部分は期待であって実証ではない。

**D. 企画ページ(手紙)の出口**
- 誰が・いつ: X から手紙企画に来た人(11/9 に117人)。締切前にもう一度告知があれば、もう一度来る。
- 増えるもの: 手紙を書いた・読んだ後に、今年の曲の読みもの、自分が行った公演の記録へ進める。
- 現状と根拠: 手紙から入った人が他へ進んだのは HOME 17PV(7人)ほか数PV。手紙のページは世界観のためにヘッダーも下のタブも無い(意図どおり)。
- 既存との差: 世界観は崩さず、送信後の画面とページの終わりに、静かな出口を1〜2本だけ置く。
- 工数: 0.5日。期限つき(12/20 まで)なので、やるなら早く。
- 反論: 企画の目的は手紙であって、回遊ではない。出口が企画を安く見せるなら、やらないほうがよい。

**E. アルバム単位の読みものの入口(まず『虚構集』)**

**最小の試し方**: 個人の重ね合わせは作らない。年表の再利用と、年の集計の数ブロックだけの1ページを、12/26 の公演を入れた後、1月の第1週に出す。手紙のページの終わりに、締切後だけ出口を1本置く。

**観察すること**: 来訪、読み進んだ深さ、そこから公演ページ・読みものへ進んだ人数。カードを作るかどうかは、ここを見てから決める。来訪は「振り返りたい人がいた」まで。「来年も見に来る」は1回では分からない。

**参考にした仕組み**: Spotify Wrapped。年末という、放っておいても振り返る時機に、その人だけの記録を1枚にして渡す。効く条件は、個人の記録があることと、年に一度しか出ないこと。このサイトは参戦記録とセトリを持っているので条件の半分は満たすが、記録を付けている人がまだ少ない(DB で84人)。だから個人の部分は後回しにしている。
