# 78. サイトのチェッカースキル(site-check)

ユーザーから。「現状のサイトのパフォーマンスやアクセシビリティ、サイトデザインの質、コンテンツの内容を評価するチェッカースキルを作りたい」

調べ([plan/76](./76-site-evaluation-methods.md))、現状の評価([plan/77](./77-site-evaluation-2026-11.md))に続く 3 つ目。plan/77 を測った時のスクリプトを整えて、同じ測り方を繰り返せるスキルにした。**サイト本体(`src/`)は何も変えていない。plan/77 の 17 件も直していない。**

書き分け: **確認**=このセッションで動かして確かめた / **未確認** / **推測**。

## 1. 使い方

Claude Code で `/site-check`(全部)か、`/site-check perf` のように領域を付けて呼ぶ。「サイトをチェックして」「前回から悪くなっていないか見て」と頼んでも同じものが動く。

| 引数 | 測るもの | 測る先 | 測定の時間(今回) |
|---|---|---|---|
| `content` | サイトマップ、canonical、hreflang、title・description、JSON-LD、見出し、切れた内部リンク、画像、外へのリンク | `public/` の HTML 全部 | 1 分 |
| `a11y` | axe-core、独自チェック(lang、見出し、main、スキップリンク、押す所の大きさ)、キーボード | ローカルで配った `public/` の 38 ページ × 2 幅 × 2 テーマ | 9 分 |
| `design` | 見た目の決まりに関わる数、画面写真 | 同じ 38 ページ × 2 幅 | 4 分 |
| `perf` | Lighthouse(スマホの条件で 3 回の中央値、PC で 1 回) | 本番の 12 ページ | 10 分 |

測った後、スキルは前回の記録との差を出し、画面写真と記事を見て判断したことを足して、`plan/` に報告を書く。**測って報告するだけで、見つけたものは直さない。デプロイもしない。**

## 2. 置いたもの

`.claude/skills/site-check/`

| 物 | 役目 |
|---|---|
| `SKILL.md` | 手順、しないこと、結果の読み方(このサイトの落とし穴 10 個)、報告の形 |
| `config.json` | 測るページ、幅、独自デザインのページ、ほかの人の名前が出るページ |
| `package.json` | 測定の道具の版(lighthouse 13.6.0、axe-core 4.14.1)。サイト本体の `package.json` とは別 |
| `scripts/status.js` | 測る前の確かめ(ビルドの古さ、本番の版との違い、重い処理、ポート、道具) |
| `scripts/content.js` `extlinks.js` | 内容 |
| `scripts/serve.js` | `public/` を配るだけの小さいサーバー(`gatsby serve` より軽い) |
| `scripts/a11y.js` `keyboard.js` | アクセシビリティ |
| `scripts/design.js` `sheet.js` | 見た目の数と、画面写真を並べた 1 枚 |
| `scripts/perf.js` `cls.js` | 速さと、CLS の原因探し |
| `scripts/report.js` | 今回のまとめを `history/` に残し、前回との差を出す |
| `history/2026-11-17.json` | 最初の記録(これが次の回の比べる相手) |

生の出力と画面写真はリポジトリ直下の `.site-check/<日付>/` に出る(gitignore 済み。コミットしない)。

## 3. plan/76 で決めていなかった 2 つ

- **前回との比べの置き場所**: 回ごとのまとめ(数だけ。25KB ほど)を `history/<日付>.json` としてコミットする。生の出力(Lighthouse の JSON、画面写真。数十 MB)はコミットしない。PC を替えても比べられ、リポジトリも重くならない。
- **道具の入れ方**: スキルの中に `package.json` を置き、版を固定して `npm install --prefix .claude/skills/site-check` で入れる。サイト本体の依存には足さない(ビルドに関係ない物を混ぜない)。`node_modules` は gitignore。Playwright・cheerio・sharp はサイト本体に入っている物を使う。

## 4. 作りながら決めたこと

- **ほかの人の名前を出力に入れない**: 診断のタイプ詳細とツアーナビは、利用者の一覧の読み込みを止めてから測る。axe の例にはセレクタと理由だけを残し、要素の中の文字は残さない。セレクタの中の長い数字(投稿の番号)、エラー文の中の URL、接続先の名前も伏せる。`history/` に名前・識別子が入っていないことを確かめた(確認)。
- **独自デザインは合計から外す**: 楽曲記事のうち独自デザインを持つ 21 本(`src/components/songArticles/designs/` から自動で決まる)と、手紙・プロフィールカードは、見た目の合計に入れず、数だけ別に出す。ツアーナビは「古いデザインのまま」なので外していない。
- **速さは 1 本ずつ、本番へ**: Lighthouse は順番に動かす。途中で止まっても、同じ日なら続きから回る。
- **比べ方**: 領域ごとに「その領域を測った一番新しい回」と比べる(速さだけ測った回があっても、ほかの領域の比べは飛ばない)。道具の版が変わっていたら、その領域に注意書きを出す。

## 6. plan/77 と数え方を変えたところ

次の回から比べる相手は `history/2026-11-17.json`(今回)で、plan/77 の本文の数ではない。変えたのは次の 4 つ。

| 項目 | plan/77 | 今回 | 理由 |
|---|---|---|---|
| 絵文字 | 63 | 絵文字 34 + 記号 497 | 前は 1 ページ 12 個で打ち切っていた。打ち切りをやめ、色つきの絵(🎫 など)と、字の形の印(✓ → など)を分けた。絵文字は `/live/guide/` 25、`/bijigaku-navi/` 9 |
| 11px 未満の文字 | 811(全ページ) | 430(独自デザイン 5 ページを除く 33 ページ) | 独自デザインを合計から外した。`/letters/` の 345 は別に出る |
| 枠つきの箱 | 42 | 30 | 同上(`/card/` の 2 を外した)。ツアーナビは 13 → 3。利用者の一覧の読み込みを止めたためと見ている(推測。前の生の出力と突き合わせてはいない) |
| スマホ幅の押す所 / 24px 未満 | 2,484 / 604 | 2,378 / 589 | 利用者の一覧を止めた 2 ページの分が減ったと見ている(推測。同上) |

キーボードの「隠れる」は、固定の部品の下か画面の外にある時だけ数え、地図のピン同士の重なりは「ほかの重なり」に分けた(`/place/` で 40)。
