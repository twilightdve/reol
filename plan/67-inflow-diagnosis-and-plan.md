## 1. 結論

1. **いちばん大きい原因は「検索に載っていない」こと。** サイトマップには 2,735 ページあるが、Google で見つかるのは十数ページ(`site:` 検索で 13 件、多く見ても約25件)。公演ページ 180、曲ページ 131 は 1 件も出ない。読みものは 21 本のうち 1 本だけ。同じ題材の個人ブログは Reol の公演ページが約173件、ファン Wiki は約792件載っている。
2. **X では、いちばん届いた2本がサイトに来る形になっていなかった。** 遠征情報のまとめ(20,641表示)と渋谷の聖地巡礼ガイド(19,346表示)は X の中で完結していて、サイトへの流入はほぼ無い。逆に、サイトの URL を付けた記事の告知は 264〜685 表示で、ふだんの投稿(中央値 約550)と同じかそれ以下。
3. **記事 21 本のうち 13 本は、告知の投稿が見つからない。** 『虚構集』の5曲と『極彩色』の8曲。
4. **他の人がサイトの URL を投稿したのは、診断だけ。** 見つかった 45 件のうち 43 件が診断の結果で、42 件が3月。
5. 最初に試すのは次の3つ。
   - **施策1(検索・継続)**: Search Console を登録して現状を見えるようにし、公演ページと曲ページを検索に載せる。題名を「何のページか」が分かる形に直す。
   - **施策2(時機)**: 公演の当日〜翌日に、セトリと発見を画像つきで出し、公演ページへ着地させる。11/20 ANIMAX MUSIX、11/29 極秘LEGIT 大阪で2回試す。
   - **施策3(届け直し＋検索)**: X で 19,346 表示だった渋谷の聖地巡礼ガイドをサイトに置き、12/15 東京公演の前に出し直す。聖地は、検索から名前以外の言葉で人が来ている唯一の題材。
6. Search Console の数字(検索語、表示回数、クリック、掲載順位、インデックス状況)は**取得できなかった**。必要な資料は 10章。

### S1. 検索に載せる土台(届け直し。継続)

- **誰に**: 公演名・ツアー名・曲名と「セトリ」で探す人。行った公演を確かめたい人、行けなかった人、次の公演の予習をする人。フォロワーの外。
- **どこで**: Google の検索結果。
- **何を見て開くか**: 題名に、公演名・会場・日付・「セットリスト全◯曲」が揃っていること(見本は 6章)。
- **着地**: 個別の公演ページ → 曲ページ → 読みもの・公式。
- **やること**:
  1. Search Console に登録し、サイトマップを送る(ユーザーの作業。DNS の TXT で確認する「ドメイン プロパティ」なら、サイトの変更もデプロイも要らない)。
  2. 「ページのインデックス登録」で、載っていない理由の内訳を見る。ここで 3-2 の推測を確かめ、次を決める。

## 8. 継続の案と、時機の案

| | 継続して検索で見つかる案 | 公演・リリースの時機に合わせる案 |
| --- | --- | --- |
| 該当 | S1、P1 の検索の面、N1 | T1、P1 の X の面、R1、N2 |
| 届く相手 | フォロワーの外。名前を知っていて調べる人 | フォロワーと、その先。フェスの場合は外 |
| 効果が出るまで | 載るまで数日〜数週間、流入として見えるまで早くて数週間。**このサイトでの実測は無い** | 当日〜3日(実績どおり) |

| 確かめ方 | Search Console の表示回数・掲載順位・インデックス数 | GA の当日の新規ユーザーと入口。X の表示回数 |
| 危うい点 | 載らない理由がまだ分からない。直しても載る保証は無い | 運営者のアカウントの届く範囲が上限。公演の日に動けること |

**両方やる理由**: 時機の案は今ある経路(X)で確実に小さな山を作るが、山と山のあいだは何も残らない。継続の案は当たるか分からないが、当たれば山のあいだを埋める。時機の案で作った公演ページは、そのまま検索の受け皿になる。

## 付録. 調査の範囲と限界

- 検索結果の順位は、運営者がログインしているブラウザでの1回ずつの確認。個人向けに寄っている可能性があり、順位そのものは参考。「載っているか・いないか」は `site:` と完全一致の検索で確かめたが、`site:` は全件を返さないので件数は概数(`/welcome/` のように、`site:` に出ないが載っているページがある)。
- GA4 のきれいな期間は 10/30〜11/11 の13日。それより前は混入があり、桁と順位だけを見た。GA の MCP は接続に失敗したので、同じ権限の読み取り API を直接使った。
- X の数字は、X の検索が返した範囲。投稿の取りこぼしがありうる。表示回数は取得した時点の値。リンクのクリック数は外から見えない。他の人の投稿は、アカウント名を記録していない。
- 「表示に対して来た割合」は、同じ日の別の投稿、他の人の投稿、リポスト経由が混ざる。目安として使う。
- 公演の後に何が検索されるか(検索の量)は測れていない。検索結果に誰がいるかを見ただけ。
- ファン Wiki、個人ブログ、note は、検索結果に出た題名と件数だけを見た。中身は読んでいない。
- 載らない理由(3-2)と、外からのリンクの効果(N3)は推測。
- iPhone 実機、言語版の画面、聖地のデータの中身(新宿の周辺に何があるか)は、今回見ていない。
