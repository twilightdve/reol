## 1. LIVE 一覧の開ける行の印

### 前

- 行の右に「^」(上向きの山形)。開くと向きが変わる。
- 山形は「上へ戻る」の丸いボタンと同じ形で、開けることが伝わりにくかった。
- 開いた公演の行(セットリストを開ける行)は、閉じている時に何も出ない(狭い画面)。

### 今

- 閉じている行は「＋」、開いた行は「−」。縦の線が縮んで「−」になる。
- 「＋」の左に、開くと出るものの数を出す。ツアーの行は「N公演」(2 公演以上の時)、公演の行は「N曲」。
- 矢印の形は使わない(「→」はページへ移る印、「詳細」は公演のページへ移るボタン。開く・閉じるとは別のもの)。
- 行のどこを押しても開くのは前と同じ。

### 一緒に直した不具合

印のボタンが、押せる行の中に入っていて、ボタンを押すと「ボタン」と「行」の両方が動き、開いてすぐ閉じていた(結果として何も起きない)。ボタンの側で行へ伝えないようにした。印を続けて押して、閉→開→閉→開と切り替わるのを 2 つのブラウザで確かめた。

変えたファイル: `src/components/index/live/enhanced-timeline-item.tsx`(`ExpandMark`、`handleToggleButton`)。

## 4. 新しく登録した公演が載らない理由

### 分かったこと(確認)

- ビルドは、シートの `live`(ツアー・イベント)と `live_item`(公演)を読む時、**uuid の列が空の行を外す**(`gatsby-node.ts` の `createLiveNodes`)。公演は、親の uuid(`liveUuid`)でツアーに結び付ける。
- uuid・slug・親の uuid の列は、行を足しただけでは入らない。シートのメニュー「UUID 移行」(`scripts/gas/`)を動かした時に、空のセルにだけ入る。
- 2026-11-14 0 時台にシートを読んだ状態:

| シート | 行 | 中身 | 状態 |
|--------|----|------|------|
| `live` | 80 | Reol Installation Concert 2027「音沙汰」 | uuid・slug が空 → ビルドで外れる |
| `live` | 81 | MIKITOP Tribute Live | uuid あり |
| `live_item` | 174 | 神奈川 2027-01-13 ビルボードライブ横浜 | uuid あり。ただし親の uuid が MIKITOP のもの |
| `live_item` | 175 | 大阪 2027-01-20 ビルボードライブ大阪 | uuid・slug・親の uuid が空 → 外れる |
| `live_item` | 176 | 東京 2027-01-25 ビルボードライブ東京 | 同上 |
| `live_item` | 177 | 2027-02-11 東京ガーデンシアター(MIKITOP) | 同上 |

- その結果、サイト(手元のデータも公開中のデータも同じ。79 ツアー・173 公演)では「音沙汰」が出ず、「MIKITOP Tribute Live」の中身が横浜のビルボードライブの公演になっている。

### 推測

`live_item` の 174 行目に入っている uuid・slug・親の uuid は、もともと MIKITOP の公演の行のもので、行を足した時にこの 3 つのセルだけ元の位置に残った。

### 直し方(シートの操作。ユーザーが行う)

1. `live_item` の O174:Q174(uuid・slug・親の uuid)を切り取って、O177:Q177 に貼る(MIKITOP の公演に、もとの uuid を戻す)。
2. メニュー「UUID 移行」→「全シートに UUID/slug 列を付与」を動かす(空のセルにだけ入る。`live` 80 行目と `live_item` 174〜176 行目が埋まる)。

こちらはシートを読むことしかできない(書けない)。操作のあとで読み直して確かめる。サイトに出るのは次のデプロイの時。

### 気づいたこと(直していない)

`live` の日付の範囲に、区切りが半角の「~」の行と、`2026/12/15` のような書き方の混ざった行がある。コードは「〜」で区切る。今の表示に崩れは見えていないが、並びや期間の扱いで食い違う可能性がある(未確認)。

### 直したあとの読み直し(2026-11-14 追記)

ユーザーがシートを直したあとで読み直した。

| 確かめたこと | 結果 |
|-------------|------|
| uuid が空の行(`live`・`live_item`) | 0 |
| 親の uuid が `live` に無い公演 | 0 |
| 「音沙汰」(`live` 80 行目) | uuid・slug が入った。公演は横浜・大阪・東京の 3 つが結び付いている |
| MIKITOP(`live` 81 行目) | 公演は東京ガーデンシアター(2027-02-11)の 1 つ。uuid はもとのもの |

サイトの画面ではまだ確かめていない(次のデプロイのビルドでシートを読み直す)。

slug だけ、もとの位置に残っている。`live_item` 174 行目(横浜)の slug が MIKITOP の uuid の末尾のままで、177 行目(MIKITOP)は重なりを避けた `…-2` になった。このまま出すと、今 MIKITOP の公演のページになっている URL が横浜の公演のページになり、MIKITOP は新しい URL へ移る。出す前に 2 つの slug を入れ替えると、MIKITOP の URL は変わらない。
