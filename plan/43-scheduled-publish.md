# 43. 楽曲記事の予約公開

依頼(2026-10-13): 「予定公開機能を作りたい。デプロイはしておいて、公開開始時刻を過ぎないと表示されないようにする。ただ、プレビュー用にURLを知っていれば見れるようにしておきたい」

## 方式

サイトは静的配信(GitHub Pages)で、公開日時に再ビルド・再デプロイはしない(デプロイは頼まれた時だけ。定期実行のデプロイは作らない)。
そのため、**静的HTMLはビルド時刻で判定し、ページを開いた後に JS で今の時刻と比べて、公開日時を過ぎていれば出す**。

- 公開日時(`publishedAt`)が未来の記事 = 予約公開。新しい状態の値は作らない。
- 記事ページ `/articles/<slug>/` は予約中でも作る。URL を知っていれば読める(プレビュー)。
  - 公開日時の前は、ページの上に「公開前のプレビューです(公開予定: …)」と出す。過ぎたら出さない。
  - noindex にはしない(公開日時を過ぎても、次のデプロイまで静的HTMLに残ってしまうため)。
- 公開日時を過ぎるまで出さない場所(静的HTMLには出さず、JS が今の時刻で判定して過ぎていれば出す):
  1. 読みもの一覧 `/articles/`(アルバムの絞り込みの件数も)
  2. シリーズのページ `/articles/series/*`
  3. ほかの記事の「その他の記事」(予約中の本数だけ候補を多めに渡し、ページ側で外して3本にする)
  4. 曲ページの「この曲の記事」
  5. HOME の読みもの欄(`HOME_ARTICLE_IDS` に入れた場合)
- サイトマップ: ビルド時点で予約中の記事は載せない(`pageContext.scheduled`)。

## 使い方

```
npm run articles:publish -- --id reol-song-047 --revision 4 --at "2026-10-15 20:00"
```

- `--at` は日本時間(「2026-10-15 20:00」「2026-10-15T20:00」)か、タイムゾーン付きのISO形式。曖昧な書き方は拒否する。
- 予約中の記事は `--at` で日時を変えられる。`--at now` で今すぐ公開に切り替え。公開済みの記事の公開日時は変えない(拒否)。
- 予約中に本文を差し替えても、更新日時は付けない。
- その後はいつもどおり OGP を撮ってコミット・デプロイ。

## 仕組み

- `src/utils/songArticles/schedule.ts`: `isReleased(publishedAt, now)` と `useNow(builtAt)`。`useNow` は最初の描画でビルド時刻を返し、表示後に今の時刻へ切り替える(静的HTMLとの食い違いを避ける)。ページを開いたまま公開日時を迎えても出るよう、1分ごとに更新する。
- `gatsby-node.ts`: ビルド時刻 `BUILT_AT` を各ページ情報(一覧・シリーズ・記事・曲ページ・HOME)に `builtAt` で渡す。記事ページに `scheduled`。
- `gatsby-config.ts`: サイトマップから `scheduled` のページを除く。

## 制約(承知の上で採った)

- 予約中の記事の題名・URL・冒頭の一文は、一覧のページ情報(`page-data.json`)には入っている。画面にも静的HTMLにも出ないが、技術的には事前に読める。
- JS が動かない閲覧者・検索エンジン・サイトマップには、公開日時の後の最初のデプロイで載る。
- HOME の読みもの欄の記事は、これまでどおり `HOME_ARTICLE_IDS` で手で選ぶ。

## 確認(2026-10-13)

- エンドを一時的に2時間後の予約にしてビルド(確認後に元へ戻した。コミットしていない)。
  - 静的HTML: 記事ページはあり・noindex なし・プレビューの注記あり。一覧・シリーズ・ほかの記事の「その他の記事」・曲ページ・サイトマップには無い。
  - ブラウザ(WebKit・Chromium)で時計を公開日時の前・後にずらして確認。前: どこにも出ず、注記あり。後: 一覧・曲ページ・ほかの記事3ページの「その他の記事」に出て、注記は消える。静的HTMLとの食い違いの警告なし。
- `--at` の読み取り: 日本時間の2つの書き方とタイムゾーン付きISOは読み、「2026/10/15 20:00」・タイムゾーンなしの秒付き・「tomorrow」は拒否。
