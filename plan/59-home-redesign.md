## 2. 問題(Fable の相談をもとに整理)

1. **一番強い絵が HOME に出ていない。** 記事の表紙は雑誌の表紙として通用する。それなのに HOME では文字だけの枠で、しかも下の方にある。記事カードのクリックが少ない(1本2〜3)のは、置き場所と見た目のせいだと推測。
2. **どのカードも同じ見た目で、優先順位が読めない。** EXPLORE、入口カード、MORE TOOLS、診断カードがどれも「枠線+小さい文字」。LIVE の導線は EXPLORE と入口カードに重複している。
3. **ファーストビューがぼやけたサムネに取られている。** さらに PC では下部タブとヘッダーが二重になっている。

## 3. 推奨する HOME の構成(日本語版)

雑誌の表紙のように特集の記事を先頭に置き、アーカイブはその下に層を分けて並べる。

| 順 | セクション | 中身と見た目 |
|---|---|---|
| 0 | MainVideo | HOME だけ細い帯(サムネ+曲名+再生)に畳む。押すと今の大きさに戻る。iframe は外さず、CSS だけで畳む(ページをまたいだ再生を壊さない) |
| 1 | 特集の記事 | 表紙を大きく出す。スマホは全幅、PC は表紙が2/3で、題・シリーズ・日付・「読む」が1/3 |
| 2 | 読みもの棚 | ほかの記事の表紙カード。スマホは手で横にスクロール、PC は4列。シリーズのチップと「全17本を読む」 |
| 3 | TODAY 帯 | NEXT LIVE と ON THIS DAY を1本の帯にまとめる。チケットのボタンは塗りに格上げ |
| 4 | ARCHIVE | EXPLORE と入口カードを4〜6枚のタイルにまとめる。統計の数字はタイルに入れる(DISCOGRAPHY に128曲など) |
| 5 | TOOLS | MORE TOOLS・診断・参戦ガイド・タイムマシンを1つの索引にまとめる(スマホ2列) |
| 6 | ABOUT | 「Reolのこれまでと、これからを知る。」を締めの帯にする |
| 7 | PICK UP POST | そのまま |

- **特集の1本**:今の `HOME_ARTICLE_IDS` と同じく、手で固定する。「最新の1本」を画面側で選ぶと、静的 HTML と表示が食い違ったり、予約公開の記事が漏れたりする。
- **HOME の記事カードに出すもの**:題・曲名・シリーズ・日付だけ。要約は出さない(歌詞の引用が混じる可能性があるため)。
- **日本語以外の4言語**:読みものは日本語のみなので1・2を出さず、今のヒーロー見出しを先頭に残す。
- **やらないこと**
  - 表紙に色を被せたり、トリミングしたりしない(記事ごとの独自デザインが要件)。
  - 自動で回るカルーセルは使わない。
  - LIVE の導線を下げすぎない。HOME で一番押されているのは公演情報・セトリ(66)。

## 4. サイト全体で連動して変える点(優先順)

1. **ナビに「読みもの」を足す。** ヘッダーに足し、下部タブは PC では隠す。下部タブには6枠目として足す(日本語のときだけ)。
2. **表紙付きの記事カードを共通の部品にする**(`ArticleCoverCard`)。差し込み先は、HOME と記事末尾の「その他の記事」(今は文字だけ)。
   - 記事を入口にした直帰率は高い(53〜92%)。記事末尾の改善も HOME と同じくらい効くと推測。
3. **カードの見た目を3階層に絞る**:絵付きのカード、ARCHIVE のタイル、索引の行。
4. **DISCOGRAPHY・LIVE の一覧にも、公式のジャケット・サムネを出す。**
5. **MainVideo のサムネを `hqdefault` 以上にする**(全ページ)。

### カルーセル(2026-11-04 ユーザー「横スクロールもいいけどカルーセル形式にしない？」)

- `ArticleCarousel`(新規)を HOME の読みもの欄と、記事の最後に使う。
  - スマホは1枚ずつ見せ、左右の矢印と下の点で切り替える。指で横にめくることもできる(scroll-snap)。
  - HOME は md、記事の最後は sm 以上で3列(どちらも3本なので一度に見える)。
- 自動では送らない。読んでいる途中で動くと読みにくく、止める操作も要るため。
- 確認:Chromium・WebKit の 390 で次を確かめた。
  - 矢印で次へ進むと、点が2本目に移る。
  - 点で1本目に戻れる。
  - 最後までめくると、点が3本目になる。
  - 768・1280 では3列で、矢印・点は出ない。
  - 横にはみ出さない。

### 自動送り・10本(2026-11-04 ユーザー「カルーセルは時間経過で自動で次を表示するようにしてね。表示件数は10枚はどう？」)

- **10本**
  - HOME の読みものは、公開日時の新しい順に10本(`HOME_ARTICLE_COUNT`)。
  - 手で選んでいた3本(`HOME_ARTICLE_IDS`)の固定はやめた。新しい記事が自動で先頭に出る。
  - 限定公開は出さない。予約公開の分は多めに渡し、HOME 側で公開日時を過ぎるまで外す(関連記事と同じやり方)。
- **カルーセル**
  - HOME はどの幅でもカルーセル。スマホ1枚・sm 2枚・md 3枚ずつ見せる。
  - 点の数は先頭に置ける位置の数(PC は8、スマホは10)。
  - 記事の最後(3本)は、スマホだけカルーセル。
- **自動送り**
  - 5秒ごとに次へ送り、最後まで来たら先頭に戻る。
  - 止める時:
    - マウスを載せている間(マウスの時だけ。iPhone はタップで mouseenter が来て外れないため)
    - 触れている間、キーボードで中にいる間
    - 画面の外にある時、タブが裏にある時
    - 「視差効果を減らす」の時(最初から送らない)
  - 一時停止・再開のボタンを付けた。
- **確認**(Chromium・WebKit)
  - HOME の 390・1280 で、次をすべて確かめた。
    - 5秒ごとに 0→1→2 と進む。
    - マウスを載せると止まる。
    - 一時停止ボタンで止まる。
    - 最後から先頭に戻る。
  - 「視差効果を減らす」の時は動かない。
  - 記事の最後は、390 で進み、1280 では3列で動かない。
  - 横にはみ出さない。
- **別件の修正**: PICK UP POST などの読み込み中のくるくる(`LazyComponent`)。
  - 枠の高さが0で relative も無く、HOME の中央(読みもの欄の上など)に12個重なって出ていた。
  - 枠の中に出るように直した。本番の今の HOME でも出ていた不具合。

### 下部タブの間隔(2026-11-04 ユーザー「LIVE, PLACE, PHOTO の間隔が空きすぎているように見える」)

- 6つを同じ幅(`w-1/6`)で並べていたので、DISCOGRAPHY だけ文字が長く、短いタブの間が空いて見えた。
- `flex-auto` にして、各タブの幅を「文字の幅+余りの等分」にした。文字と文字の間隔がそろう。
  - 390 では 27px、360 では 22px、430 では 33px。Chromium・WebKit とも同じ。
- `min-w-[44px]` も試した。WebKit では幅の配分の計算が変わり、間隔がそろわなくなるのでやめた。
  - 360 の LIVE は幅 43px になるが、高さが約 56px あるので押しやすさはほぼ変わらない。
- 下部タブだけ DISCOGRAPHY を「DISCO」と短く出す(2026-11-04 ユーザー指定)。
  - 読み上げ(aria-label)とヘッダーのナビは元の名前のまま。
  - 間隔は 390 で 33〜34px、360 で 28〜29px にそろった。いちばん細いタブも 49px になった。
