# 74. まだ生で聴いていない曲の一覧

2026-11-15。ユーザーから。

- 「いま行ったことのあるLIVEをチェックできる機能があるけど、チェックしたLIVEのセトリの曲はLIVEで聴いたことがある曲として判定し、まだLIVEで聴いたことのない曲を一覧で見れる機能がほしい」

## 1. 前

- LIVE のページに「生で聴いた曲 N / M」の集計はあった(plan/27 ステップ5)。参戦済みにした公演のセットリストに載っている曲を数える。
- まだ聴いていない曲は、その下の折りたたみの中に小さな札で並ぶだけ。聴いた曲が 1 つ以上ある時にしか出ない。演奏回数も、最後に演奏された公演も分からない。

## 2. 今

### 一覧のページ `/live/unheard/`

- 上に「生で聴いた曲 N / M ・ P%」と棒、「参戦済み K公演 ・ まだ聴いていない曲 N曲」。
- 印が 1 つも無い時は、全部の曲を並べて、「行った公演に ✓ を付けると、その公演の曲がこの一覧から外れます」と LIVE の一覧への行を出す。
- 並び順は「演奏回数の多い順」(初期)と「最近演奏された順」。
- 一覧は 3 つに分けた。

| 節 | 中身 | 出し方 |
|----|------|--------|
| Reol の曲 | 楽曲データに結び付いている曲(113) | 曲名、最後の演奏(日付・公演名)、演奏回数。行を押すと曲のページへ |
| まだライヴで演奏されていない曲 | セットリストに一度も載っていない曲(16) | 曲名だけ。「生で聴いた曲」の数には入れない |
| カバー・ライヴだけの演目 | 楽曲データに結び付かない演目(120) | 初めは閉じている。開くと名前・最後の演奏・回数 |

- 各言語版(en・ko・zh-hans・zh-hant)も同じ作りで出る。中国語・韓国語の文言は機械翻訳。
- ビルド時の HTML には全部の曲が並び、ブラウザで参戦済みの印を読んだあとに聴いた曲が外れる(印はこの端末のブラウザの中にある)。

### 入口

- LIVE のページの集計の下に「まだ生で聴いていない曲を見る N曲」の行。印が無い時も出る。前の折りたたみ(小さな札)は外した。聴いた曲の折りたたみとシェアカードは前のまま。
- 「できること」のページの LIVE の欄。

## 3. 聞かずに決めたこと

1. **MC などを曲から外した。** シートで種別が曲のままになっている、曲ではない行(「-MC-」「（MC）」「質問コーナー」「抽選会」「演奏者・ダンサー紹介」、中止・出演キャンセルの注記)を、名前で外す。LIVE のページとシェアカードの分母も同じ数え方になり、233 になる(前は 239。手元の計算で、公開中の画面の数字は読み直していない)。
2. **カバーなどは閉じた節に分けた。** 共演者の曲やメドレーが Reol の曲と同じ並びに混ざると、目当ての一覧が読みにくいため。分母(233)には前と同じく入っている。
3. **まだ演奏されていない 16 曲は別枠。** 「聴いていない」のは確かだが、聴く機会が無かった曲なので、数には入れずに下へ置いた。

## 4. 作り

- 数え方を `src/utils/heardSongs.ts` の 1 か所にまとめ、LIVE のページ(`LiveSection.tsx`)と新しいページが同じ関数を使う。同じ曲は songUuid(無ければ正規化した曲名)でまとめる。最後の演奏は、公演日のうち一番新しい日。
- 開閉の印(＋／−)を `src/components/redesign/ExpandMark.tsx` に出して、LIVE の一覧と共用にした。
- 新しいファイル: `src/pages/live/unheard.tsx`、`src/i18n/site/pages/unheard.ts`、`src/utils/heardSongs.ts` とそのテスト、`ExpandMark.tsx`。
- 変えたファイル: `LiveSection.tsx`、`enhanced-timeline-item.tsx`、共通の辞書 5 言語(`unheardList` → `unheardLink`)、`features.ts`、`features.tsx`。

## 6. データで気づいたこと(直していない。シートの側)

- 「-MC-」などの行は、種別を segment にすると、名前で外す処理に頼らずに済む。
- 楽曲データに結び付いていないセットリストの表記がある(「感情御中」「水底遊歩道」「ストリーミングハート」「(Remix)」など)。結び付くと「Reol の曲」の側で数えられ、閉じた節から消える。
