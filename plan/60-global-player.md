# 60. MainVideo をやめて、どこからでも再生できるプレイヤーにする

2026-11-04 ユーザー「mainVideoも無くして良いかも」「代わりにもっと色んな場所にプレイヤーを配置して、再生中の動画はスクロールしたり画面遷移しても右上隅で継続再生されるようにしたい」。
plan/59 の段4(MainVideo を HOME で帯に畳む)は、これに置き換える。

## 1. 今の状態

- 全ページの一番上に MainVideo(`mainVideo.tsx`)がある。XFD を順に流すだけで、どの動画を出すかは選べない。スクロールすると右上に縮む。
- ページの中の動画は、それぞれが別々に YouTube を埋め込んでいる(ディスコグラフィ・曲ページ・公演ページ・今日は何の日・聖地・ようこそ・記事)。
  - ページを移ると、その場で止まる。
  - 2つ同時に鳴ることがある(MainVideo とページの中の動画)。
- 縦長の動画(PHOTO の投稿)は `LazyYoutube` / `StaticYoutube`。

## 2. 作り

- **プレイヤーは1つだけ。** `GlobalPlayer` を `Body`(wrapRootElement)に置き、ページを移っても外さない。
  - iframe は DOM の中で動かすと読み込み直しになり、止まる。なので **DOM の位置は変えず、CSS の position だけを切り替える。**
  - `document.body` 直下に1回だけ portal で置く。
- **動画の場所は「枠」(`PlayerSlot`)。** 枠はサムネイルと再生ボタンだけを持つ。押すと、その動画を GlobalPlayer で再生する。
  - 枠が画面に見えている間:プレイヤーは枠の上にぴったり重なる(`position:absolute` で、ページの座標に置く。スクロール中に JS で追わなくてよい)。
  - 枠が画面の外に出た時、別のページへ移った時:右上隅の小さい窓(`position:fixed`)に移り、そのまま流れ続ける。
  - 戻ってきたら、また枠の上に重なる。
  - 小窓には「閉じる」(止めて消す)と「動画の場所へ」(同じページに枠がある時だけ)。
- 同時に鳴るのは1本だけ。ほかの枠を押すと、そちらに切り替わる。
- 再生は全部、利用者が押した時だけ。音を消して自動で流すことはしない(MainVideo の `mute=1` はやめる)。
- 埋め込みは `youtube-nocookie.com`(プライバシーポリシーの記載どおり)。
- 再生リスト(`videoseries`)も同じプレイヤーで流す。
- Relive(独自の再生室)では小窓を隠して止める。

## 5. iPhone で1回押すだけで流す(2026-11-06)

- ユーザー: 「現状2回再生ボタン押さないといけないのなんとかならない？」。
- 原因: 押した後に iframe を作っていた。iPhone・iPad・Mac の Safari は、押した後に作った iframe の autoplay を音ありでは通さず、YouTube の再生ボタンをもう一度押させる。
- 1回目の直し(7141e412c8): 読み込めた時点で API から `playVideo()` も呼ぶ。→ ユーザーの iPhone で「相変わらず2回」。Safari はページ側の押した操作を別のドメインの iframe に渡さないので、API からの指示も通らない。
- 2回目の直し: 押す指が YouTube のプレイヤーそのものに届くようにする。
  - 対象は iPhone・iPad(Mac と名乗る iPad はタッチの点の数で見分ける)と Mac の Safari だけ。Chrome などは前のまま(押した後に作る)。
  - 画面に6割以上見えている枠のうち一番見えているものに、見えない(opacity 0)プレイヤーを1つだけ重ねて用意する。用意した枠は見える割合が3割を切るまで替えない。スクロールの途中で作り直さないよう 0.3 秒待って選ぶ。
  - 用意したプレイヤーは autoplay を付けず、押されるまで流さない。押せる範囲は真ん中だけ(`clip-path: inset(56px 12% 44px 12%)`)。YouTube の上の帯(題・チャンネル・共有)などが見えないまま押されないように。外れた所は下の枠に届き、前と同じ動き(押した後に作る)。
  - 流れ始めた(PLAYING)ら、その枠で再生を始めたことにし(playMedia)、見えるようにする。iframe は同じ要素のまま(鍵と autoplay の値を変えない。変えると react-youtube が作り直す)。
  - 再生を止めたら、次に用意するプレイヤーは作り直す(gen)。用意したプレイヤーは Tab で入らず読み上げもしない。枠のボタンをキーボードで押した時は、用意したプレイヤーのまま API で流す(Safari では通らず、YouTube の再生ボタンをもう一度押すことがある)。
  - プライバシーポリシーの YouTube の記載と plan/29 を、この動きに合わせて直した。
- 確認(開発サーバー、Chromium に iPhone の UA・WebKit、390px):
  - 記事(mede:mede)を開くと用意したプレイヤーが枠にぴったり重なり、12秒たっても流れない(autoplay=0)。HOME では枠が画面に入るまで YouTube を読み込まない。傾けた枠(ハルシアン)・シネマスコープの枠(ミュータント)にもぴったり重なる。
  - 枠の真ん中を押すと YouTube が流れ始め(PLAYING)、同じ iframe のまま枠の上に見えるようになる。小窓 → 閉じる → 戻ると、作り直したプレイヤーが流れないまま用意される。キーボードで枠のボタンを押すと、用意したプレイヤーのまま再生に移る。
  - Chromium のふだんの UA では前と同じく、押すまで iframe を作らない。
  - ヘッドレスの Chromium では、流れ始めて 0.3〜0.5 秒で止まる(PAUSED)。本番の前の版でも同じなので、検証環境の動き。Playwright の WebKit は YouTube の動画を流せない。iPhone で1回で流れるかは実機で確かめてもらう。
