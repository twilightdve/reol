# 48. プロフィールカード(ライヴ会場での自己紹介)

着手(2026-10-18): ユーザー「ライヴ会場で開演前や打ち上げ等で知り合った人に自己紹介するためのプロフィールカード作成機能を作りたい」。

## 0. ユーザーの決定(2026-10-18)

- 渡し方: **スマホの画面に出して見せる**/**QR コードで相手に渡す**/**画像として保存・SNS で送る**(3つとも)
- 載せる項目: **名前・アイコン・好きな曲**/**Reol タイプ診断の結果**/**参戦記録**/**SNS の ID・ひとこと**
- 会員・非会員の両方が使える。非会員は一部の機能に制約があること、情報が消えることがあることを明示する。

## 1. 提案(要承認)

### 1-1. ページ

- `/card/`: カードを作る・見せる(作る人の画面)
  - 上: カードのプレビュー。下: 項目の入力と「載せる/載せない」の切り替え。
  - 「見せる」ボタン: 画面いっぱいにカードと大きな QR。暗い会場でも読めるよう黒地に白の大きな文字。画面が消えないようにする(Wake Lock。使えない端末では何もしない)。
  - 「画像で保存」: カードを PNG にする。iPhone は共有シート(写真に保存・DM で送る)、PC はダウンロード。
- `/card/view/#…`: QR・リンクを受け取った人が見るページ。noindex。

### 1-2. QR の中身: カードの内容そのもの(サーバーに置かない)

- QR は `/card/view/#<カードの内容を圧縮した文字列>`。`#` 以降はブラウザから外に送られないので、カードの内容はサーバーにもアクセス解析にも残らない。
- 会員・非会員で同じ仕組み。会員のIDから他人のカードを引ける公開ページを作らないので、IDを知られても何も見えない。
- 渡した時点の内容の写しになる(あとで書き換えても、渡した QR の中身は変わらない)。名刺と同じ。
- 受け取った側のページには「このカードは作った人が入力した内容をそのまま表示しています」と書く(サイトは本人確認をしていない)。
- 表示は文字としてだけ出す。SNS は決まったサービスのドメイン+ID の形を確かめた時だけリンクにする。長さの上限を決め、読めない・壊れた中身は「読み取れませんでした」。

### 1-3. 項目と、どこから持ってくるか

| 項目 | 会員 | 非会員 |
| --- | --- | --- |
| 名前 | プロフィールの表示名(カードだけ別の名前にもできる) | 入力 |
| アイコン | プロフィールのアイコン(画像) | 名前の頭文字(画像は使えない) |
| 好きな曲 | プロフィールの好きな曲(カードで最大3曲まで選べる) | 曲を選ぶ |
| Reol タイプ | 診断結果(プロフィール) | 診断結果(この端末に残っているもの) |
| 参戦記録 | 「行った」ライヴ(参戦数・はじめて行ったライヴ・直近のライヴ) | 同じ(この端末に記録したもの) |
| SNS | X・Instagram・Threads・Bluesky・TikTok の ID(各1つ) | 同じ |
| ひとこと | 60字まで | 同じ |
| 想い出のライヴ | 終わった公演から選ぶ。カードには日付を外した公演名(2026-10-21 「今日のライヴ」→「好きなライヴ」→「想い出のライヴ」) | 同じ |

- どの項目も、載せる/載せないを選べる(参戦記録などを出したくない人向け)。
- 会場選択を「非公開」にしている会員も、自分のカードには参戦記録を載せられる(自分で選んで渡すため)。

### 1-4. 会員と非会員の違い(画面に明記する)

- 非会員: カードの内容はこの端末のブラウザだけに保存。ブラウザのデータを消す・別の端末・プライベートモードでは消える。アイコン画像は使えない(頭文字)。
- 会員: カードの内容をアカウントに保存し、別の端末でも同じカードを使える。アイコン画像を使える。
- 「消えることがあります。残したい時は画像で保存するか、会員登録を」と案内する。

### 1-5. データベース(会員のカードの保存)

- `profiles` に `card` 列(jsonb。SNS・ひとこと・載せる項目の選択)を足し、本人だけが読み書きできる関数を通す(他の人からは読めない)。
- SQL はユーザーが SQL Editor で実行する(この接続は読み取り用)。SQL を書いて渡す。
- SQL を流すまでは、会員もこの端末だけに保存する形で動く(先に画面を作れる)。

### 1-6. 画像

- カードを canvas に描いて PNG にする(画面の見た目をそのまま写す方式は、外部のアイコン画像やフォントで崩れやすいため)。
- 画像には QR も入れる(画像を受け取った人も読み取れる)。

### 1-7. 入り口

- メニュー(プロフィールのサイドメニュー)・ライヴのページ・HOME の小さな導線。

## 2. 進め方

1. 1章の承認を受ける。
2. 画面(作る・見せる・受け取る)を作り、Chromium・WebKit のスマホ幅で確認 → 限定公開ではなく機能なので、確認用のデプロイの扱いを聞く。
3. 会員の保存用 SQL を渡す → 実行後につなぐ。

## 3. 実装(2026-10-18、ユーザー「その方針で進めて」)

- 1章のとおり。変えたところ:
  - アイコン: アイコン画像を登録している会員は0人で、登録する機能も無いため、全員「名前の頭文字」(色は Reol タイプの色)。
  - アクセス解析: gatsby-plugin-google-gtag はページ表示の page_path に `#` 以降を含めるため、`/card/view/` はページ表示を送らない(gatsby-config の exclude)。受け取る画面は読んだらすぐ URL から `#` 以降を消す(再読み込み用にそのタブの sessionStorage にだけ残す)。noindex・サイトマップから除外・referrer を送らない。
  - サイト共通の動画プレーヤー: `/card/`・`/card/view/` ではミニに固定し、消音の間は隠す(楽曲記事と同じ)。
- ファイル: `src/pages/card/index.tsx`(作る・見せる)、`src/pages/card/view.tsx`(受け取る)、`src/components/profileCard/`(見た目・保存・画像)、`src/utils/profileCard/codec.ts`(中身の形と確認)、マイページのメニューに「プロフィールカード」。
- 会員の保存: `supabase/features/supabase-profile-card.sql`(profiles.card 列、get_my_card / set_my_card、change_user_id に card を写す)。ユーザーが SQL Editor で実行する。実行前は会員もこの端末だけに保存(画面にもそう出る)。
- 確認: 単体テスト(中身の往復・壊れた中身・長さ・SNS の形)、型チェック。Chromium・WebKit のスマートフォン幅と PC 幅で、入力 → プレビュー → 見せる → リンクで受け取る画面、画像で保存。保存した画像と「見せる」画面の QR を macOS の Vision で読み取り、カードのリンクになっていることを確認。
- 本番ビルド(gatsby serve)で確認: 受け取る画面ではページ表示を送らず、スクロールの計測の page_location も `#` 以降が消えた `/card/view/`(GA への送信は記録して止めた)。作る画面で静的HTMLとの食い違いのエラー無し(Chromium・WebKit)。
- SQL は 2026-10-18 に実行済み(card 列は anon から読めない・関数2つ・change_user_id に card)。ログイン時の verify_user_login / sign_up_user が返すプロフィールにも本人の card が入る(本人の分だけなので問題なし)。
- 未確認: 会員(ログイン)での保存の動き(本物のアカウントでのログインが要るため、ユーザー確認)。iPhone 実機での共有シート・カメラでの読み取り(ユーザー)。

## 4. 試験中は運営だけ(2026-10-18)

- ユーザー「一旦自分だけが見れる機能にして」。
- `/card/`: 運営(`src/constants/owner.ts` の OWNER_USER_ID = twilightplc)のログイン時だけ作る画面を出す。それ以外(静的HTMLを含む)は「このページは準備中です」。noindex・サイトマップから除外。
- マイページのメニューの「プロフィールカード」も運営だけ。
- `/card/view/`: リンク・QR を受け取った人は誰でも見られる(運営が渡したカードを、ログインしていない相手が読むため)。「カードを作る」の案内は運営にだけ出す。
- 表示の切り替えで、閲覧の制限ではない(静的サイトなので、ページのプログラム自体は誰でも取れる)。会員の保存用の関数も、ログイン中の本人なら誰でも呼べる。
- 確認: 開発サーバーの Chromium・WebKit で、ゲスト・他の会員・運営の3通り(ログイン状態は localStorage で再現、Supabase への通信は止めた)。
- 元に戻す: `src/constants/profileCard.ts` の `PROFILE_CARD_OWNER_ONLY` を `false` にしてデプロイする(作る画面・メニュー・受け取る画面の案内・noindex・サイトマップの除外がまとめて元に戻る)。

## 5. 好きな曲を選択式に・保存ボタン(2026-10-20)

- ユーザー「好きな曲は選択式にして / オリジナルとcoverの欄を3:2で分けて」「入力項目は保存できるようにして」。
- オリジナル3曲: 曲ページ・楽曲ソーターと同じ代表曲(songStats)から選ぶ。最初に入った作品ごとにまとめて、新しい作品から並べる。
- カバー2曲: ディスコグラフィの「歌ってみた」の作品名から選ぶ(新しい順)。カードの中身は `c`(FAVORITE COVERS として表示・画像にも入る)。
- 同じ曲はほかの欄で選べない。前に手で入れた、一覧に無い曲はそのまま残る(選び直すまで)。
- 「保存」ボタンと保存の状態を足した。会員はすぐアカウントへ送る(保存待ち → 保存済み、失敗時は表示)。自動保存(この端末はすぐ・アカウントは0.8秒後)も続ける。ページを離れる時に保存待ちがあれば送る。
- 確認: 開発サーバーの Chromium・WebKit(運営ログインを localStorage で再現、Supabase の get/set_my_card は記録して偽の応答)。選択・重複不可・保存ボタン後の送信内容・再読み込み後の復元・横はみ出し無し・静的HTMLとの食い違いエラー無し。

## 6. スタイルを選べるように・好きなライヴ(2026-10-21)

- ユーザー「Spotifyみたいにシェアカードはスタイルをいくつか選べるようにしたい」「今日のライヴは好きなライヴに変更。これも選択式にして」。
- スタイル4つ(`components/profileCard/cardStyles.ts`): ダーク(今まで)・カラー(Reol タイプの色のグラデーション)・ライト・!Legit(公式の青と黄)。プレビューの下の丸い見本から選ぶ。画面・「見せる」・画像・受け取る画面すべて同じ見た目。カードの中身は `y`(ダークの時は入れない)。
- 好きなライヴ: 終わった公演(今日まで)を、ツアー・ライヴごとに新しいものから選ぶ。カードでは「FAVORITE LIVE」の欄(前の右上の札はやめた)。前に入れた「今日のライヴ」は意味が違うので引き継がない。
- 画像の折り返しで、行の頭に空白が残っていたのを直した。
- 確認: 開発サーバーの Chromium・WebKit(運営ログインを再現)。4スタイルの切り替え・画像4枚・保存内容(style・favoriteLive)・受け取る画面のスタイル・未来の公演が出ないこと・横はみ出しと静的HTMLとの食い違いエラー無し。

## 7. アイコン画像(2026-10-21)

- ユーザー「アイコンに画像を設定できるようにしたい。ただ画像はサーバで保存しない」。
- 画像はこの端末の localStorage にだけ置く(`useCardIcon.ts`。真ん中を正方形に切り抜いて 256px の JPEG、数十KB)。カードの中身(QR・リンク・アカウントへの保存)には入れない。QR に収まらず、入れるとサーバーにも残るため。
- 画像が出るのは、作る画面のプレビュー・「見せる」画面・「画像で保存」したカード。QR・リンクで受け取った人の画面は頭文字のまま。この違いは入力欄の説明に書いた。
- 確認: 開発サーバーの Chromium・WebKit(運営ログインを再現)。画像を選ぶとプレビューに出る・アカウントへ送る中身に画像が入らない・リンク(141文字)にも入らず受け取る画面は頭文字・画像で保存したカードに入る・再読み込み後も残る・「外す」で消える・静的HTMLとの食い違いエラー無し。

## 8. LIVE参戦の書き方(2026-10-21)

- ユーザー指定: 「LIVE参戦 / 全73公演（美辞学、UNBOX、...）」。カッコの中は参戦した公演の多いツアー。

- ツアー名は `tourShortName`(utils/profileCard/tourName.ts): Reol / れをる のライヴだけ、「」『』"" の中、無ければ年の後ろ(Reol Oneman Live 2026 美辞学 → 美辞学)。フェス・対バンはそのまま(カッコの中だけだと誰のライヴか分からなくなるため)。

## 9. アイコンの範囲を選ぶ(2026-10-21)

- ユーザー「画像の切り取り領域を編集できるようにしたい」。
- 画像を選ぶと範囲を決める画面(`IconCropper.tsx`)。丸の中がアイコン。ドラッグで動かす・スライダー / 2本指 / ホイールで拡大(1〜4倍)。Esc・「やめる」で閉じる。
- あとから「位置を調整」できるよう、元の画像(長い辺 1280px の JPEG)と範囲も localStorage に置く(サイトには送らない)。置けない時はアイコンだけ(位置の調整は出ない)。前の版で選んだアイコンは元の画像が無いので、選び直すと調整できる。
- 「LIVE参戦」のツアーの続きは「、…」→「等」(ユーザー指定)。
- 確認: 開発サーバーの Chromium・WebKit。拡大2倍とドラッグ → 決める → 範囲(元画像の px)と元の画像が保存・カードに反映・再読み込み後に「位置を調整」で同じ位置から開く・Esc で閉じる。2本指の拡大は自動テストでは試せていない(iPhone で要確認)。
