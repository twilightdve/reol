**懸念2**: 着地ページ `(not set)` が120セッションあり、直帰率96.7%・エンゲージ率3.3%とほぼ全数離脱している。

**[2026-07-16 追調査]** ブラウザ/OS/流入元でクロス集計したところ、Safari(iOS)・Chrome(Android)・Safari in-app・Android Webview・Edge(Windows)など特定環境に偏らず広範囲に分散していた。`gatsby-config.ts` で `gatsby-plugin-offline`(Service Workerによるオフライン対応/プリキャッシュ)が有効になっており、Gatsby+GA4構成における`(not set)`着地の既知要因と一致する(確度: 推測、実機トレースでの確証はなし)。オフライン対応とのトレードオフであり、該当120セッションを除いてもコア指標への影響は軽微なため、**現時点ではコード変更を行わず様子見**と判断した。

**技術的な不具合を発見**: 着地URL一覧に以下がそのまま出現していた。

```
/relive/?setlistId=live_71_item_1?setlistId=live_71_item_1
```

`?setlistId=...` が二重に連結されたURLで、21セッションがこの壊れたURLから着地している。

**[2026-07-16 追調査で訂正]** コード調査の結果、URL生成箇所は `templates/live-item.tsx` の `` `/relive/?setlistId=${slug}` `` の1箇所のみで、`location.search`とのマージや`history.pushState`等の書き換えを行うコードは存在しなかった。サイト側のコードバグではなく、**X等で手動シェアされたリンク自体にクエリが重複していた**(コピペミス等)可能性が高いと判断し、対応不要とした。

**最重要指標が事実上計測できていない**: `src/utils/analytics.ts` のコメントに「サイトの最重要指標(公式への送客)を計測する」と明記されている `official_link_click` が、90日で**わずか11件**。14,000PV規模のサイトでこれは極端に少ない。原因として:

1. 公式リンクボタン自体の視認性・配置が弱い可能性
2. `official_link_click` を発火するボタンが設置されているページ(`song.tsx`, `live-item.tsx`, `HomeSection.tsx`, `welcome.tsx` 等)への流入が、サイト全体トラフィックの主力(`/quiz/reol-type/quiz/`)から遠い可能性
3. 単純にユーザーが公式送客に至る前に離脱している

**カスタムディメンション未登録**: `get_custom_dimensions_and_metrics` で確認したところ、GA4管理画面にカスタムディメンションが**1件も登録されていない**。`trackEvent` は `category` / `label` などのパラメータを送信しているが(例: `report_click` の `label` に記事名、`filter_change` の `label` にフィルタ種別)、GA4側でカスタムディメンションとして登録しない限り、探索レポートやピボットで `label` 単位の内訳を見ることができない。今回 `entry_card_click` の内訳を取得しようとしたが、`label` が空扱いで返り、どのカードがクリックされているか個別に分からなかった。

## 6. 改善提案

### P0(計測基盤・すぐ効く)

1. **カスタムディメンションの登録**(GA4管理画面、コード変更不要)
   `event_category` を「イベントスコープ」のカスタムディメンションとして登録する。特に `report_click` の `label`(記事名)、`entry_card_click` の `label`、`filter_change` の `label` を見えるようにするだけで、「どの導線が実際にクリックされているか」が初めて可視化できる。
   **Why**: 現状はイベント発火数しか見えず、意思決定に使えるレベルの粒度がない。

2. **`/relive/?setlistId=...` の二重クエリパラメータバグ修正**
   21セッション分の着地URLが壊れている。シェア文言生成 or Relive PlayerへのリンクURL組み立て箇所を特定し修正する。
   **Why**: バグの直接的な実害(該当URLが正しく機能しない可能性)に加え、計測上もノイズになっている。

3. **`(not set)` 着地(120セッション、直帰率96.7%)の原因調査**
   X公式アプリ内ブラウザ(in-app browser)での計測欠落が典型的な原因。`gatsby-ssr.tsx` のgtag読み込みタイミングや、X in-app browserでのUTM/リファラー扱いを確認する。
   **Why**: 全セッションの6%が計測上ほぼ無効になっており、実際の流入実態を過小評価している可能性がある。

### P1(導線改善)

4. **`/live/` 単体着地時の直帰率67.8%への対策**
   X投稿から `/live/` 一覧へ直接着地したユーザーの離脱が高い。
   **[2026-07-16 対応済み]** `LiveSection.tsx` に「直近の開催予定/開催中」バナーを追加。`live.json`の日程データから今日以降にも公演日が残る最も近いライブを算出し(`enhanced-timeline-item.tsx`の`isOngoingTour`と同じ日付抽出方式)、タグフィルタの壁より前に表示。クリックで該当ライブの詳細まで自動スクロール(`useDeepLinkScroll`用に`id="live-<slug>"`をトップレベルカードにも追加)。`next_live_banner_click`イベントで計測。
   **Why**: `t.co` 経由の大量流入がこの着地パターンで無駄になっている可能性。

5. **`official_link_click` を増やす導線設計**
   最大の集客源である `/quiz/reol-type/quiz/` → `/quiz/reol-type/result/` の診断結果画面に、公式リンク(YouTube/ストリーミング)への導線が弱い場合は強化する。
   **[2026-07-16 対応済み]** 調査の結果、result画面には`official_link_click`計測がゼロ(公式リンク自体が未設置)だった。`welcome.tsx`の「ここから先は、公式で。」CTAパターンを流用し、result画面のリトライボタン直後(タイプ詳細/全タイプ一覧より上、目に留まりやすい位置)に公式サイト/公式YouTubeへのCTAを追加。既存の`trackOfficialLinkClick`で計測、i18n(ja/en)キーも追加。
   **Why**: 診断コンテンツが圧倒的な集客力を持つのに、そこから公式送客(サイトの最重要KPI)へのブリッジが薄い。

### P2(中期・SEO)

6. **Organic Search強化の検討**
   Organic Searchが7.4%(149セッション)と小さく、X依存からの脱却余地が大きい。曲詳細ページ・会場ページなど、検索意図に応えられるロングテールコンテンツが既に大量にある(`/bijigaku-navi/venue/*` など)ため、構造化データ・内部リンク・メタ情報の再点検で伸びる可能性がある(詳細は既存の `06-seo-sns.md` を参照)。

7. **リピート率向上施策**
   新規ユーザー比率96.6%は、施策が奏功すれば伸び代が大きい指標でもある。ツアー期間中のプッシュ通知的な仕組み(既存のPWA化検討があれば)や、次回ライブ・新曲通知のニュースレター的導線を検討。
