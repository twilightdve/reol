## DB(`supabase/features/supabase-birthday-letters.sql`、ユーザーが SQL Editor で実行)

テーブルは RLS 有効・ポリシーなし・anon / authenticated から REVOKE(user_sessions と同じ)。読み書きはすべて SECURITY DEFINER の関数経由。

- `birthday_letters`: カード ID、編集鍵のハッシュ、送信の重複防止キー(request_id、unique)、今の版、確認済みの版、Web に出さない(運営判断)、取り下げ・抜き取りの日時。
- `birthday_letter_versions`: **投稿・修正のたびに 1 版**。宛先、宛名、差出人、SNS、絵柄、本文、公開範囲。印刷は版を指して記録するので、後から何を刷ったか再現できる。
- `birthday_letter_print_batches` / `_print_items`: 印刷の束。束を作った時点で各カードの版を固定し、運営が「印刷した」と押した時だけ印刷済みにする(印刷画面を開いただけでは記録しない)。
- 印刷状況は版から出す: 未印刷 / 印刷済み / 再印刷が必要(印刷した版 ≠ 今の版)/ 抜き取りが必要(印刷済みで取り下げ)。

本文は HTML ではなく JSON(段落 → 文字のかたまり。太字・色 4 種・大きさ 3 段・左寄せ / 中央寄せだけ)。DB 側で形・値・長さを検査し、表示・印刷は React で文字としてだけ出す。

### 非公開本文の守り

- 一般向けの関数は「確認済み・取り下げていない・Web に出す」カードの **確認済みの版** だけを返し、「贈る本だけ」の本文は SELECT しない。
- 本人の関数は編集鍵のハッシュが合う時だけ全文を返す。運営の関数は、ログイン中の ID が `birthday_letter_admins` に覚えた運営で、**プロフィールの作成日時も一致する** 時だけ(SQL を実行した時点の twilightplc を覚える。ID は名前なので、運営が ID を変えたり退会したりした後に他人が同じ ID を取っても運営にならない。運営が ID を変えたら、この表を直すまで運営の関数は使えない)。フロントの OWNER_USER_ID は表示の出し分けだけ。
- 呼び出しはすべて POST(supabase.rpc)なので、Service Worker(gatsby-plugin-offline)にも残らない。
- 本人が後から直した所は、再確認を待たずに古い内容を下げる(本名を消した、などがすぐ効くように): 本文を「贈る本だけ」に変えた・本文を直した → 本文を出さない(直した時は「修正の確認中」の札)、SNS を外す・変えた → SNS を出さない、差出人の名前か宛名を変えた → カードごと出さない。広げる変更(本だけ → Web公開)は再確認まで効かない。
- 修正画面と運営画面は GA を読み込んでも送らない(`ga-disable-<ID>` を head の先頭で立てる)。修正 URL の # の鍵が、履歴の変化で送る計測に拾われないように。
- 印刷: 束を作った後に取り下げられた手紙は印刷画面に出さず、「印刷した」でも記録しない(画面を開いた後に取り下げられたものは刷った記録が残り、「抜き取りが必要」に出る)。
- 運営画面は他のサイトの枠(iframe)の中では何も出さない(GitHub Pages ではヘッダーで止められないため)。
- 運営は、本人が取り下げた手紙を戻せない(運営が取り下げたものだけ戻せる)。
- 宛名・差出人・本文の見えない文字・向きを変える文字(U+202E など。なりすましに使える)は DB が拒む。画面は貼り付け時に落とす。絵文字のゼロ幅接合子は通す。

### DB の容量を守る上限(2026-11-07 時点の DB は 13MB)

| 対象 | 上限 |
| --- | --- |
| 投函(全体) | 10 分に 120 通・1 日 1000 通 |
| 修正(1 通) | 30 版まで・10 分に 10 回 |
| 修正(全体) | 1 日 1000 回 |
| 本文 | 1,200 字・JSON で 16KB |

上限いっぱいに荒らされても 1 日 32MB ほど。全体の上限なので、荒らしが上限を使い切ると、その間は本物の投函も「混み合っています」になる(送信元ごとの制限は、Supabase で送信元の IP を確かに取れるか未確認のため入れていない)。

### 残る弱いところ(2026-11-07 の見直し)

- 投函・修正の上限は全体の数なので、荒らしが使い切るとその間は本物の投函も止まる。送信元ごとの制限は、Supabase の関数から送信元の IP を確かに取れるか未確認のため入れていない。

- 修正用の鍵は投函した端末の localStorage に覚える。共用の端末では、次に使う人が直せる。

## SQL 実行後の確認(書き込みはしない)

読み取りだけで `birthday_letter_admins` に twilightplc が 1 行入っている(入っていなければ運営画面が forbidden になる)。anon キーで: 5 つのテーブル(`birthday_letters` / `_versions` / `_print_batches` / `_print_items` / `_admins`)の直接 SELECT がすべて拒否される / `rpc/letters_admin_list` が forbidden / `rpc/_letters_clean` が呼べない / `rpc/letters_public_list` が `[]`。試しの投函を本番 DB に入れる時はユーザーに確認する。
- 時期を 5 つに(2026-11-08、ユーザーの指示): 今のReol → REOLの頃 → あにょすぺにょすゃゃの頃 → れをるの頃 → しぇりーの頃。しぇりーは、れをるより前に名乗っていた名前(作品の記録はないので、曲の画面を飛ばして宛名へ)。あにょすぺにょすゃゃは『No title-』などの名義から。それ以外の名義(Reol & nqrse など)は、れをる / REOL / Reol のうち日付の近い時代へ。→ **SQL の再実行が必要**(era に sherry / anyo を許す)
- 宛名は選んで作る(2026-11-08、ユーザーの指示): 自由入力をやめ、「前につける言葉(選んだ曲・作品の名前の / あの頃の / あの日の / つけない)」「名義(Reol / REOL / あにょすぺにょすゃゃ / れをる / しぇりー)」「呼び方(様 / 氏 / さん / 呼称なし)」のドロップダウン。れをるの既定は「れをる氏」(「れをる様」はやめた)。前に自由に書いた宛名は、選び直すまでそのまま。宛名・差出人の画面ではカードの表だけを見せる
