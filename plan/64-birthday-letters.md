## 作り

サイトは SSG(GitHub Pages)。手紙は **ビルドに一切入れない**。ページはすべてブラウザーで Supabase の関数(RPC)から読む。

| パス | 内容 |
| --- | --- |
| `/letters/` | 入口(Happy Birthday, Reol)→ 年表から宛先を選ぶ → 表面 → 本文(装飾エディター)→ 公開範囲と完成形の確認 → 投函 |
| `/letters/read/` | 届いた手紙の一覧(宛名面)。時代・宛先で絞り込み。ランキングなし |
| `/letters/card/?id=` | 1 枚の個別ページ。公開本文だけ読める |
| `/letters/edit/#<id>.<key>` | 本人の確認・修正・取り下げ。鍵は # の後ろだけ(GA・サーバーに渡らない。読んだら URL から消す)。noindex、GA 除外 |
| `/letters/admin/` | 運営(twilightplc)だけ。確認、Web 掲載の可否、印刷の束づくり、印刷画面、印刷済みの記録、再印刷・抜き取りの一覧。noindex |

- 全体のテーマ(黒背景・ヘッダー・下部タブ)は被せない(body.tsx の relive / design-preview と同じ扱い)。ページが自前の見出し・下部ナビを持つ。
- 書体は Noto Sans JP / Noto Serif JP をこのページだけ Google Fonts で読む(全ページ共通 CSS に入れない方針のため)。CSS もページの Head に置く。
- OG 画像は企画で 1 枚(静的サイトなのでカードごとの OG は作れない)。本文は OG・meta に一切入れない。

## DB(`supabase/features/supabase-birthday-letters.sql`、ユーザーが SQL Editor で実行)

テーブルは RLS 有効・ポリシーなし・anon / authenticated から REVOKE(user_sessions と同じ)。読み書きはすべて SECURITY DEFINER の関数経由。

- `birthday_letters`: カード ID、編集鍵のハッシュ、送信の重複防止キー(request_id、unique)、今の版、確認済みの版、Web に出さない(運営判断)、取り下げ・抜き取りの日時。
- `birthday_letter_versions`: **投稿・修正のたびに 1 版**。宛先、宛名、差出人、SNS、絵柄、本文、公開範囲。印刷は版を指して記録するので、後から何を刷ったか再現できる。
- `birthday_letter_print_batches` / `_print_items`: 印刷の束。束を作った時点で各カードの版を固定し、運営が「印刷した」と押した時だけ印刷済みにする(印刷画面を開いただけでは記録しない)。
- 印刷状況は版から出す: 未印刷 / 印刷済み / 再印刷が必要(印刷した版 ≠ 今の版)/ 抜き取りが必要(印刷済みで取り下げ)。

本文は HTML ではなく JSON(段落 → 文字のかたまり。太字・色 4 種・大きさ 3 段・左寄せ / 中央寄せだけ)。DB 側で形・値・長さを検査し、表示・印刷は React で文字としてだけ出す。

### 非公開本文の守り

- 一般向けの関数は「確認済み・取り下げていない・Web に出す」カードの **確認済みの版** だけを返し、「贈る本だけ」の本文は SELECT しない。
- 本人の関数は編集鍵のハッシュが合う時だけ全文を返す。運営の関数は request_session_user_id() = 'twilightplc' の時だけ。フロントの OWNER_USER_ID は表示の出し分けだけ。
- 呼び出しはすべて POST(supabase.rpc)なので、Service Worker(gatsby-plugin-offline)にも残らない。

- SQL: PGlite(手元の Postgres)で 56 項目。Supabase と同じ既定の権限(新しい関数・テーブルを anon に直接開く)を再現した上で、テーブルを直接読めない・内部関数を呼べない・本だけの本文が一般向けに出ない・運営以外は運営の関数を使えない・再送で二重にならない・古い版からの修正は conflict・束を作っただけでは印刷済みにならない・締切の境界(14:59:59Z は受付、15:00:00Z 以降は不可)。**本番 DB ではまだ確かめていない**(SQL 未実行)。
- 本番 DB の読み取り(2026-11-07): pg_default_acl で関数・テーブルが anon に既定で開く設定を確認 → 内部関数は anon / authenticated からも REVOKE。既存の `_issue_session` などは anon から呼べないことを確認。
