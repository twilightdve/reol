# 80. ツアー・連続公演のページ(/live/tour/<slug>/)

ユーザーから(2026-11-19)。「LIVEの詳細画面も作ったほうが良いんじゃないかと思った」

## 1. 決めたこと

- **作るのは、公演が 2 つ以上ある LIVE だけ(20 件)。** ユーザーが選んだ。
  - LIVE は 80 件、公演は 176。公演ごとのページ(`/live/<公演>/`)は前からある。
  - 1 公演だけの LIVE(60 件)は、公演ページが詳細ページの役をする。LIVE のページを作ると同じ中身が 2 つになり、検索でどちらを出すかもぶれる。
  - 公演が 2 つ以上ある LIVE(最大 24 公演)には、ツアー全体を見る場所が無かった。共有できるのも LIVE 一覧の `#live-…` だけだった。
- **URL は `/live/tour/<LIVE の slug>/`。** `/live/<slug>/` は公演ページが使っていて、LIVE と公演で同じ slug のものがある(`big-forest-live`、`luckyfes23`)。`/live/tour/` の一覧ページは作らない(LIVE 一覧がその役)。
- **5 言語。** `src/utils/i18nRoutes.ts` の翻訳するルートに足した。

## 2. ページの中身

`src/templates/live-tour.tsx`。公演ページと同じ並びで、箱は使わず行と罫線(plan/71)。

| 並び | 中身 |
|---|---|
| 題名 | 公演の色(LIVE 一覧のワンマンと同じ決まり。白・黒・灰に寄る色は無彩色) |
| 日程・公演数・公式サイト | シートの値 |
| 映像 | LIVE の YouTube(ある時だけ) |
| 公演一覧 | 日付・会場・名前・曲数。各公演ページへ |
| 演奏された曲 | 下の 3 |
| Spotify・LIVE REPORT・関連ポスト | シートの値(ある時だけ) |

## 3. 演奏された曲の数え方

- 分母は**セットリストが登録されている公演**。全公演ではない。文も「セットリストが登録されている 3 公演(全 6 公演のうち)」と書き、全公演にそろっている時だけ「全 N 公演で演奏」と書く。
- 同じ公演で 2 回演奏した曲は 1 と数える。MC など(`type: segment`)と空の行は数えない。
- 曲ページへの結び付けは公演ページと同じ(songUuid → 代表曲、無ければ曲名)。曲ページがある曲は曲ページの名前で出す(公演ごとの注記「(途中で中止)」を、ツアー全体の名前にしない)。
- セットリストが 1 公演だけの時は、数えずにその公演ページへ案内する。0 の時は「まだ登録されていません」。
- 開催中のツアー(始まっていて終わっていない)は、LIVE 一覧と同じく、注意を読んで押してから出す。同意は一覧と共有する(`spoiler-ack-<liveUuid>`)。2026-11-19 の時点で開催中のものは無い(これからが 3 件、どれもセットリスト 0)。

## 4. 入口

- LIVE 一覧: 公演が 2 つ以上ある LIVE を開くと、右上に「まとめ」(折りたたみ中も HTML にある)。
- 公演ページ: 題の下の LIVE 名と、「OTHER DATES —『…』」の LIVE 名が、ツアーのページへ。

## 5. 一緒に直したこと

- LIVE 一覧のワンマンの色と、開催中の判定を `src/utils/liveTour.ts` にまとめ、一覧とツアーのページで同じものを使う。テストあり(公式の青になるのはライト 3 件・ダーク 4 件)。
