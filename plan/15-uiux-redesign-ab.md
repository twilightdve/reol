## 1. 現状UI/UXの評価

### 1.1 強み(維持・活用すべき資産)

| # | 資産 | 根拠 |
|---|---|---|
| S1 | **圧倒的な独自データ** — 130曲の詳細ページ、演奏統計、セトリ、ロケ地マップ、年表、診断 | 他に無い。デザインが伝えるべき最大の価値 |
| S2 | **権利配慮の設計思想**(公式埋め込み/リンクのみ) | 信頼性の源泉。ただし「アーティスト写真をヒーローに使えない」という視覚設計上の制約でもある |
| S3 | **旧openingのBLACKBOX意匠**(黒×オレンジ #ea6000)がコードに現存 | `opening.tsx` の `renderUnbox` 系 + `tailwind.config.js` のunbox/shutterアニメ。現行openingは空と雲に置き換わり済みで未使用だが、Reolらしい強い意匠として復活可能 |
| S4 | **作品ごとのテーマカラーをデータに保持** | `discography.themeColorPrimary/Secondary` + `dynamic-colors.css` の下地。ほぼ未活用 |
| S5 | 直近バッチの導線整備(タグライン、入口3カード、公式フッター、共通状態UI、reduced-motion対応) | 第1〜4バッチ実装済み |

### 1.2 課題

| # | 課題 | 根拠(ファイル) | 影響 |
|---|---|---|---|

| W6 | ダークモード非対応・emoji依存のアイコン(🔰🎤📊) | 各所 | 質感の低下(特にOS/ブラウザ差) |

### 1.3 総評

コンテンツ(S1)は既に一級品だが、**視覚がコンテンツの価値を下回っている**。
特に W1(配色の無秩序)と W5(タイポ不在)は「個人サイトっぽさ」の主因で、ここを直すだけで印象が大きく変わる。
また S3(眠っている旧BLACKBOX意匠)/S4(未活用のテーマカラー列)という「持っているのに使っていない意匠資産」があり、B案はこれを主役に据える。

## 2. A案 — 「空と雲」を磨き上げる(現状の延長線)

**コンセプト**: 現在の空/雲/ゴールドの親しみやすい世界観は変えない。
「配色トークンの統一 × 情報の階層 × ナビの常設」で、手作りの温かさを保ったまま**編集された安心感**を出す。

### 2.1 デザイントークンの導入(基盤)

- Tailwind theme を意味ベースに再編: `brand.gold #D2AF57` / `brand.blue #27489b` / `surface`(白系3段階)/ `ink`(文字3段階)/ `accent`(1色のみ)
- **カードスタイルを1種に統一**: `bg-white/90 + border + shadow-sm`(backdrop-blurは廃止か限定)。text-shadow全廃
- 雲背景は維持しつつ `opacity-70 → 35〜40` に低減、カード外のみに見せる(可読性W4対策)

### 2.2 ファーストビュー再構成

- ヘッダー直下 = **タグライン(大)+ 検索ボックス + 入口3カード**。テキストがLCPになる
- MainVideoは「▶ Now Playing — 公式XFD」ラベル付きカードとしてタグラインの下へ格下げ(desktopは右カラム)。常設再生の仕組みはそのまま
- openingは現行維持(空と雲の演出は本編と整合しており、0.5s自動フェードも済み)

### 2.3 配色・コンポーネント統一(W1対策)

- 入口3カード+診断+美辞学バナーを**同一コンポーネント・同一ベース色(紺)**に統一。区別は左ボーダーのアクセント色とアイコンのみ
- emoji → `react-icons` の線画アイコンに置換
- ヘッダーピルもブランド2色に統一

### 2.4 ナビの常設(W3対策)

- desktop: ヘッダーに常設テキストナビ(DISCOGRAPHY / LIVE / PLACE / PHOTO / TIMELINE + 検索)
- mobile: 下部タブバーを**5タブ+全ページ常設**に再設計(保留中のP2-1「モバイル下部タブバー」をここに統合)
- ABOUTダイアログはフッターへ移設し、ヘッダーはナビに専念

### 2.5 タイポグラフィ(W5対策・小)

- 和文ディスプレイ書体を1つself-host(例: **Zen Kaku Gothic New** または **M PLUS 1p**、woff2で400/700の2ウェイトのみ)。見出し・タグライン・数字に適用。本文はシステムのまま
- 数字は `tabular-nums`(統計サイトとして効く)

### 2.6 評価

| 観点 | 評価 |
|---|---|
| 訴求力向上 | 中(第一印象の「整い」が大きく改善。世界観の驚きは現状維持) |
| 工数 | **約2バッチ**(トークン+トップ再構成で1、ナビ+全ページ波及で1) |
| リスク | 低。既存ページの構造を保ったままスタイル差し替え中心。SSG影響なし |
| 常連への影響 | ほぼ無し(見慣れた世界観のまま) |

## 3. B案 — 「BLACKBOX / CHRONICLE」訴求力第一の再設計

**コンセプト**: コードに眠っている**旧オープニングのBLACKBOX意匠(黒×オレンジ)を復活させ、本編まで貫通**させる。
Reol本人の世界観(ハイコントラスト、ネオン、エッジの立ったタイポ)に寄せたダークベースの上で、
このサイト最大の資産である**「14年分のデータ」が動くこと自体を演出**にする。
「箱を開けたら、14年分のアーカイブが起動する」— 復活させたBLACKBOX開封から本編までが一つの物語になる。

### 3.1 訴求力の源泉(写真が使えない制約下で)

アーティスト写真・アートワークの転載はできない(S2)。それでも訴求力を出す手段は4つ:

1. **巨大タイポグラフィ** — 言葉と数字そのものをビジュアルにする
2. **動くデータ** — カウントアップする統計、伸びる年表。アーカイブサイトにしかできない説得力
3. **era別ダイナミックカラー** — 既存の `themeColorPrimary/Secondary`(S4)を全面活用し、作品/年代ごとにアクセント色が変わる
4. **公式埋め込みの見せ方** — 黒地の「シアター」フレームでYouTube埋め込みを主役級に見せる(埋め込み自体は公式のみ・従来通り)

### 3.2 ビジュアルシステム

- **ベース**: ほぼ黒 `#0b0b10` / 文字 `#f2f0eb`(純白でなく僅かに温度)
- **シグネチャアクセント**: BLACKBOXオレンジ `#ea6000`(旧opening由来。CTAと「現在」を示す色)
- **ダイナミックアクセント**: era・作品別に `themeColor*` から注入(dynamic-colors.cssのCSS変数基盤を昇格)
- カードは**ダークガラス+アクセント1pxボーダー**の1系統のみ。emoji全廃
- タイポ: 和文ディスプレイに**エッジのある角ゴ/アンチック系**(例: Shippori Antique B1)+欧文コンデンス。巨大数字を多用

### 3.3 トップページ構成

1. **ヒーロー = フルスクリーンタイポ+統計ティッカー**
   「Reolの14年を、ぜんぶ遡れる。」を画面幅いっぱいの巨大タイポで。背後に
   `130 SONGS / ◯◯ LIVES / ◯◯◯◯ PERFORMANCES` がカウントアップ(ビルド時データ焼き込み、JSは演出のみ)
   +「今日は◯年前、△△があった日」(日付ベースの静的計算)
2. **クロニクルストリップ**: 2012→2026 の横スクロール年代ナビ(れをる時代/REOL/Reolのera chip)。全コンテンツへの入口をここに集約
3. **入口カード**(welcome/live/stats)はダークガラスで統一、その下に Now Playing シアター
4. **旧BLACKBOXオープニング(`renderUnbox`系・現在未使用)を復活**させ、開封演出が黒い本編に着地する構成にする(現行の空と雲openingはA案側で維持)

### 3.4 展開方針(段階導入)

全ページ一斉改修はリスクが高いため:

- **Phase B-1**: トップ+曲詳細ページ+statsの3面だけダークテーマ化 → `entry_card_click` / `official_link_click` / 滞在を現行と比較
- **Phase B-2**: 効果確認後に discography / live / place / photos へ展開
- 美辞学ナビ(和紙テーマ)は現状も別テーマとして分離済み(`body.tsx`)なのでそのまま併存可

### 3.5 評価

| 観点 | 評価 |
|---|---|
| 訴求力向上 | **高**(世界観の一貫性+「本人らしさ」+SNSでシェアされた時の見栄え。ダーク基調はOG画像too) |
| 工数 | **約4バッチ**(トークン/ヒーロー/クロニクルで2、全ページ展開で2) |
| リスク | 中。全面ダーク化はコントラスト管理・長文可読性の設計力が要る。常連の見慣れた空テーマを失う(段階導入+期間限定の告知で緩和) |
| 制約適合 | ◎ 写真転載ゼロのまま成立する設計。公式送客CTA(オレンジ)はむしろ目立つ |

## 4. 比較まとめと推奨

| 観点 | A案(延長線) | B案(BLACKBOX/CHRONICLE) |
|---|---|---|
| 第一印象の変化 | 「整った」 | 「Reolのサイトだ」 |
| opening演出との関係 | 現行の空と雲openingと整合(変更不要) | 旧BLACKBOXオープニングを**復活**させ物語の起点にする |
| 工数 | 約2バッチ | 約4バッチ(段階導入可) |
| 失敗時の戻しやすさ | 容易 | Phase B-1に限定すれば容易 |
| 既存資産の活用 | S5(直近バッチ) | S3(旧opening意匠の復活)+S4(テーマカラー列) |
| 実装時期 | いつでも | **7/10ツアーファイナル後推奨**(会期中の大規模見た目変更は避ける) |

**推奨**: 二者は排他ではない。**A案2.1〜2.4(トークン/ファーストビュー/配色統一/ナビ)はB案でもそのまま前提になる基盤**なので、
「A案を第5バッチ以降で先行実施 → B案Phase B-1をトップ+曲ページで検証 → 計測を見て全面展開」のハイブリッドが最も安全に訴求力を最大化する。
純粋に訴求力第一で一方を選ぶなら **B案**。
