# 28. !Legit の多言語対応(英語・中国語 繁体字/簡体字・韓国語)

作成日: 2026-09-28
ステータス: 第1弾・第2弾・第3弾(ガイド・On This Day・診断)実装完了(2026-09-28)。相関図のみ未着手

## 0. 決定事項(ユーザー確認済み)

| 項目 | 決定 |
|---|---|
| URL | 言語別URL。日本語は従来どおり `/`、ほかは `/en/`・`/zh-hant/`・`/zh-hans/`・`/ko/` の配下に静的生成する |
| 中国語 | 繁体字(台湾・香港向け)と簡体字(中国本土向け)の両方 |
| 範囲 | 主要ページから段階的に進める |
| 固有名詞 | 曲名・アルバム名・会場名は原語のまま。公式の英題があれば併記する(例: 煽げや尊し(Agitate))。翻訳するのは UI・見出し・説明文だけ |

hreflang の値は `ja` / `en` / `zh-Hant` / `zh-Hans` / `ko` / `x-default`(=日本語)。Google は ISO 15924 のスクリプト指定(zh-Hant / zh-Hans)に対応している(Search Central「ページのローカライズ版について Google に知らせる」で確認)。

## 1. 設計

### 1-1. 言語は URL だけから決める

- 美辞学ナビの i18next 設定は流用しない。あちらは localStorage(`reol-language`)を読むため、共有すると「美辞学ナビで英語を選んだ人に日本語ページが英語で出る」状態になり、ハイドレーション不一致が再発する
- !Legit 用に、言語ごとの型付き辞書と `t()` を用意する
- 言語をどこから得るか
  - ページ本体: `pageContext.lang`
  - ヘッダー・フッター・常設動画: `Body` のパス(ステップ3bで、ビルド時と hydrate 時に一致するようになった)
  - `<html lang>`: `onRenderBody` に渡される `pathname` から決める(現在は `"ja"` 固定)
- 美辞学ナビの言語切り替えは対象外で、変更しない

### 1-2. 言語プレフィックスの除去

- パスで判定しているロジックは、すべて `stripLangPrefix()` を通す
  - `body.tsx` の `is*Path`
  - `mainVideo.tsx` の階層判定(`/en/live/` が2階層目と誤判定されるのを防ぐ)
  - 下部タブ
  - ヘッダーのナビの現在地表示
- 共有コンポーネントの `pathname`・`location`・`navigate(` を洗い出して対応する

### 1-3. ルート定義はひとつにまとめる

- `src/utils/i18nRoutes.ts` に「どのルートが何語で存在するか」を定義し、`gatsby-node` とクライアントの両方から使う
- `localizePath(path, lang)`: 翻訳済みのルートなら言語付きURLを返し、未翻訳なら日本語URLを返す
- `/live/<公演>/` は第1弾に含める。`/live/guide|compare|heatmap|tour-heatmap|similarity-ranking|setlist-grammar/` は含めない
- `onCreatePage` での複製は、`context.lang` を持つページ(=複製済み)をスキップする。テンプレートのページは言語ごとのループで作る

### 1-4. SEO

- canonical は各言語ページ自身のURLにする。ステップ2で入れた canonical が日本語URLを指したままだと、各言語ページが検索から外れる
- hreflang は実在する言語だけを出し、`x-default` は日本語を指す
- 言語ごとに変えるもの: `og:locale`、タイトルのサフィックス、description、JSON-LD の文字列(パンくずの「ホーム」など)

### 1-5. ビルド時に焼き込まれる日本語

- テンプレートの `buildDescription` と Head の description
- `gatsby-node` がページに渡す文字列(「N曲収録」など)
- シート由来のフォーマット名(配信SG・fullAL・歌ってみた 等)は対応表で訳す
- 日付の書式は常にロケールを明示する。ブラウザの既定値に任せると、ハイドレーション不一致になる

### 第2弾【2026-09-28 完了】

### 第3弾【2026-09-28 ガイド・On This Day 完了】

実施結果:
- ライヴ参戦ガイド(/live/guide/): 本文をセクション/ブロックのデータ(`src/i18n/site/pages/liveGuide.ts`)にして描画する。FAQPage の質問文は見出しから作るので、ページと常に一致する
- On This Day(/on-this-day/MM-DD/): 4言語 × 365ページを生成した。gatsby-node が日本語で焼き込んでいた補足行(形態・収録曲数・公演種別)と「リリース」を構造化データで渡し、テンプレート側で組み立てる。出来事の無い日の noindex とサイトマップ除外は各言語にも引き継がれる(サイトマップ掲載は各言語193日)

### 診断【2026-09-28 完了】
- ユーザー決定: 言語は他のページと同じく URL だけで決め、4言語にする。美辞学ナビの i18next(localStorage の `reol-language`)には依存しない。日本語URLでは常に日本語
- 診断ページ(トップ・質問・結果・タイプ詳細16)は専用辞書(`src/i18n/site/pages/reolType.ts`)と `src/data/reol-type/i18n/` を使う。ja/en の UI 文言は美辞学ナビの common.json と同じ。中国語・韓国語の型データと質問文は診断ページのチャンクにだけ入る
- 以前は静的HTMLに `reolType.title` などのキーがそのまま出ており、読み込みのたびにハイドレーション不一致が起きていた。辞書をビルド時に引くようにして解消した。質問ページを `?q=` 付きで直接開いたときの不一致も直した
- 画面遷移・X共有文・コピー文・シェアカードのURLは言語付き。OG画像は日本語のまま
- 歌詞の一節(quote)と曲名は原文のまま。英語版の質問文はこれまで日本語だったので新たに訳した
- 翻訳版では診断ページの下にも機械翻訳の注記を出す(診断は共通フッターを出さないため)
- はじめてのReol の診断リンクに付けていた「(Japanese)」等の注記は外した

## 4. 制約・注意

- ブラウザの言語による自動リダイレクトはしない(SEO上不利で、GitHub Pages にはサーバーもない)。マウント後に「English version available」のような案内を出すのは可
- **韓国語・中国語(繁体字/簡体字)は機械翻訳。ネイティブの確認を推奨する。** 英語も非公式訳
- OG画像は第1弾では日本語のまま
- 言語ごとにページを複製するため、第1弾でページが 1,208 増えた(302 × 4言語)。ビルド時間は約55秒から約60秒になり、ほぼ変わらない
- テンプレートのページ(曲詳細・公演詳細)は、`createPages` 内の `createPageWithLocales` で言語ごとに複製している。`onCreatePage` は、サイト自身の `createPages` で作ったページには呼ばれない
- 辞書は全ページ共通のJSに入っている(+15KB gzip)。言語が増えたり文言が増えたりしたら、言語別チャンクへの分割を検討する
